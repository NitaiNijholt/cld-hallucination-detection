\textbf{Phase 1: Generation:} The LLM generator (GPT-4.1) constructs CLDs through iterative node and edge generation, capturing uncertainty quantification (UQ) metrics for downstream hallucination detection.

\textbf{Phase 1.1: (GT Synth only) Corruption:} A Corruptor can be applied after Generation and before Judging to introduce synthetic perturbations and emit \texttt{corrupted=True/False} labels for known-ground-truth hallucinations.

\textbf{Phase 2: Judging:} An LLM judge evaluates each edge using either correctness-based reasoning assessment or citation-based verification, producing per-edge verdicts.

\textbf{Phase 3: Correction:} An LLM corrector applies tool-based fixes to flagged edges, followed by re-judging to validate corrections.

\textbf{Phase 4: Deep Research:} A multi-agent system (GPT-5 + web search) performs intensive literature validation on stratified edge samples, synthesizing evidence-based verdicts with confidence scores and source URLs.

\section{Generator}
\label{sec:generator}
%------------------------------------------------------------------------------

\textbf{Design rationale:} The generator decomposes CLD construction into edge-level decisions with mediation checks and UQ metric capture. For full motivation of the pairwise generation approach, relationship constraints, and connection to prior CLD-to-SDM pipelines, see Appendix~\ref{app:generator_design_rationale}.

\subsection{Generator implementation}
\textbf{Input:} Domain specification (target phenomenon, spatial/temporal scale, scope), optional seed node set.

\textbf{Process:} The Generator constructs CLDs through iterative node and edge generation (see Appendix~\ref{alg:cld_generation} for algorithmic details):
\begin{itemize}[noitemsep]
    \item \textbf{Node generation:} Proposes system variables relevant to the domain
    \item \textbf{Edge generation:} For each variable pair, proposes relationship type (\texttt{POSITIVE}, \texttt{NEGATIVE}, \texttt{NONE}) with causal narrative
    \item \textbf{UQ capture:} Records token-level logprobs during generation for downstream uncertainty quantification
\end{itemize}

\textbf{Output:} Complete CLD (nodes + edges with causal narratives) and per-edge UQ metrics.

\textbf{Note:} In all RQ1 and RQ2 experiments, nodes were seeded with the validation CLD node sets; node generation was disabled to isolate edge-level performance.

\textbf{Configuration:} GPT-4.1, Nitai\_C prompt, T=0.7---selected via preliminary studies (Section~\ref{sec:preliminary_studies}).

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:cld_generation}). \textbf{Input parameters (prompt):} Appendix~\ref{sec:generator_prompt_nitai_c}. \textbf{Input parameters (configuration):} Appendix~\ref{sec:generator_comparison} (Table~\ref{tab:generator_comparison_config}).

\subsection{UQ metrics implementation}
\label{sec:uq_metrics_implementation}
\textbf{Input:} Token-level logprobs from generator LLM response (when available via API).

\textbf{Process:} Four metrics are computed from the generator's completion tokens (see Appendix~\ref{alg:uq_metrics} for algorithmic details):
\begin{itemize}[noitemsep]
    \item \textbf{Perplexity:} Average token-level uncertainty with two-stage capping (token NLL capped at 20.0, average capped at 10.0) to prevent outliers from dominating
    \item \textbf{Min Probability:} Confidence floor---minimum token probability across the sequence, capturing worst-case uncertainty
    \item \textbf{Max Window Entropy:} Highest-uncertainty region detected via sliding window ($w{=}5$) over per-token entropies (top-$k{=}5$ alternatives)
    \item \textbf{Cosine Similarity:} Semantic alignment between narrative and citation chunks (citation experiments only; see Section~\ref{sec:uq_cossim})
\end{itemize}

\textbf{Output:} Per-edge UQ feature vector for downstream hallucination classification.

\textbf{Configuration:} Logprobs from OpenAI Chat Completions API (\texttt{logprobs=True}, \texttt{top\_logprobs=5}); embedding model details in Section~\ref{sec:uq_cossim}.

\textbf{Full implementation details:} Exact formulas with numerical stability measures (capping thresholds, sliding window parameters, chunking strategy) are provided in Section~\ref{sec:uq_metrics_capping}.

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:uq_metrics}).

\noindent\textbf{Token sequence note.} When available (OpenAI Chat Completions with \texttt{logprobs=True} and \texttt{top\_logprobs=5}), logprob-derived UQ metrics are computed over the model's \emph{completion} token stream exposed as \texttt{choice.logprobs.content} (a list of per-token entries with fields \texttt{token}, \texttt{logprob}, and \texttt{top\_logprobs}). This token stream corresponds to the full assistant completion for the edge call, i.e., the entire JSON string \texttt{\{"Relationship": "...", "Explanation": "..."\}} including JSON syntax and the \texttt{Relationship} label. Prompt/input tokens are not included in this API output, so these metrics reflect uncertainty in the generated output string rather than the prompt. For providers/endpoints without logprobs support (e.g., non-OpenAI models or the OpenAI Responses API), logprob-derived metrics are omitted.

\section{Corruptor (Synthetic corruption for GT Synth)}
\label{sec:corruptor}
%------------------------------------------------------------------------------

\textbf{Input:} An LLM-generated base edge table over a fixed node set \(V\) (ordered edges \((A,B)\) with relationship label and narrative), a corruption seed, and a target corruption rate \(r\in[0,1]\).

\textbf{Process:} Using an LLM-based hallucination injection methodology inspired by HaluEval~\cite{li2023halueval} for motivation corruption, applying the main edge-level hallucination types found in SD-AI's taxonomy~\cite{schoenberg2025aibuildsdmodels} and applying spurious edges and polarity flips programmatically, in 1/3 equal proportions at a corruption rate of 0.3 (meaning we apply corruption to 30\% of the edges):
\begin{itemize}[noitemsep]
    \item \textbf{Motivation corruption:} replace a valid mechanistic narrative with plausible-but-flawed reasoning while keeping the edge fixed.
    \item \textbf{Spurious edges:} convert \texttt{NONE} $\rightarrow$ \texttt{POSITIVE} or \texttt{NEGATIVE} to create false positive links.
    \item \textbf{Polarity flips:} invert \texttt{POSITIVE} $\leftrightarrow$ \texttt{NEGATIVE}.
\end{itemize}
For reproducibility, corruption is seeded; the output table preserves both original and corrupted fields for auditing.

\textbf{Output:} A corrupted edge table with a per-edge binary label \texttt{corrupted} and the corresponding corrupted content (relationship label and/or narrative). This dataset is used as GT Synth in RQ1a to evaluate judge detection under known injected errors.

\textbf{Configuration:} \texttt{model=gpt-4.1}, \texttt{temp=0.7}, \texttt{top\_p=1}, \texttt{rate=0.3}.
\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:corruption}). \textbf{Reproducibility (run commands):} Appendix~\ref{sec:execution_commands}.

\section{Judges}
\label{sec:judges}
%------------------------------------------------------------------------------

\subsection{Design rationale: LLM-as-a-Judge}
We operationalise two judge types—Correctness and Citation—based on prior work on LLM-based evaluation~\citep{zheng2024judging}. This section explains the specific scaffolding choices we adopt for CLD edge verification.

The LLM-as-a-Judge system evaluated here incorporates principles from both the hallucination detection literature and causal inference methodology.

We operationalise two judge types: Correctness and Citation-based judging.

\paragraph{Correctness Judge.}
The correctness judge evaluates whether an edge narrative is internally coherent, and is by design independent of external context. To address the gap between general hallucination detection and CLD-specific verification---where assessment requires evaluating scientific plausibility of causal mechanisms rather than surface-level coherence---we adapt the Bradford Hill Criteria (BHC) from epidemiological causal assessment frameworks~\citep{shimonovich2020bradford} as structured evaluation scaffolding. The mechanistic prompt variant operationalises four key BHC criteria (plausibility, temporality, strength, and coherence), combined with Chain-of-Thought prompting to elicit systematic reasoning~\citep{wei2022chain, kojima2022large}.

\paragraph{Citation Judge.}
For citation-based judging, we incorporate self-verification patterns from Chain-of-Verification~\citep{dhuliawala2024chain} and retrieval-augmented evidence assessment~\citep{gao2024retrievalaugmentedgenerationlargelanguage}, grounding causal claims against retrieved literature. When judging evidence retrieved from multiple sources, this thesis evaluates citations \emph{one at a time} rather than concatenating all citations into a single context window. This keeps the judging context clean and reduces ambiguity: each verdict is conditioned on a single citation's content, avoiding cross-document interference and allowing failure cases to be attributed to specific sources. These separate judge verdicts are then aggregated via majority voting, choosing the mean score as a starting point to reflect average support in the retrieved documents, although alternatives (median, top-$k$/max, or explicit reranking/selection of the best citation by a verifier model) may be more robust depending on the evidence distribution and retrieval noise (see Discussion).

Following established LLM-as-a-Judge methodology~\citep{zheng2024judging}, we employ pointwise scoring with thresholds for binary hallucination classification.

\subsection{Correctness Judge implementation}
\label{sec:correctness_judge}
\textbf{Input:} Variables, relationship type, causal narrative, prompt type.

\textbf{Process:} LLM-as-a-judge~\cite{zheng2024llmasajudge} assesses edge correctness by verifying logical/scientific coherence of the causal claim (see Appendix~\ref{alg:judge_correctness} for algorithmic details).

\textbf{Output Scores:} 0=Incorrect, 0.5=Partially correct, 1=Correct.

\textbf{Configuration:} GPT-4.1, T=0 for reproducibility~\citep{liu2023gevalnlgevaluationusing, zheng2024judging}.

\noindent\textbf{Prompt Variants}
\begin{enumerate}[noitemsep]
    \item \textbf{\PromptBaseline} (1500 max output tokens): Direct evaluation without scaffolding
    \item \textbf{\PromptMechanistic} (1500 max output tokens): Structured multi-criteria evaluation using Bradford Hill-aligned framework~\cite{shimonovich2020bradford} (Plausibility, Temporality, Strength, Coherence)
    \item \textbf{\PromptCoT} (10000 max output tokens): Chain-of-Thought prompting with explicit step-by-step reasoning~\cite{kojima2022large} and systematic evaluation of causal logic
\end{enumerate}
Full prompt texts are provided in Appendix~\ref{sec:correctness_prompts}.

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:judge_correctness}). \textbf{Reproducibility (run commands):} Appendix~\ref{sec:execution_commands} (see also Table~\ref{tab:exec_scripts}) and Appendix~\ref{sec:unified_entry_points}.
\subsection{Citation Judge implementation}
\label{sec:citation_judge}
\textbf{Input:} Variables, relationship type, causal narrative, prompt type.

\textbf{Process:} The Citation Judge implements a \textbf{generate-then-search} pipeline: it first uses Brave Search to retrieve candidate article URLs for the edge narrative (Algorithm~\ref{alg:citation_search_brave}), then fetches the corresponding full text (ContentScraper-only in the thesis configuration; Algorithm~\ref{alg:citation_fetcher}), and finally applies an LLM-as-a-judge~\cite{zheng2024llmasajudge} to determine whether each fetched source supports the causal narrative (see Appendix~\ref{alg:judge_citation} for algorithmic details).

\textbf{Output Scores:} 0=Not supported, 0.5=Partially supported, 1=Fully supported.

\textbf{Aggregate Judge Score:} Each retrieved citation is judged independently with a categorical verdict that is mapped to a scalar score:
\[
\textsc{Supported}\!\to\!1.0,\quad
\textsc{Partially Supported}\!\to\!0.5,\quad
\textsc{Contradicted/Unaddressed}\!\to\!0.0.
\]
For an edge with \(C\) retrieved citations, the aggregate citation-judge score is computed as the mean:
\[
\text{aggregate\_score}=\frac{1}{C}\sum_{c=1}^{C}\text{score}_c.
\]

\noindent\textbf{Note (mean aggregation vulnerabilities):} The mean can be brittle: it is sensitive to the number of retrieved citations, can be dominated by a single strong/weak source, and can be skewed by retrieval/fetch failures (missing-at-random is not guaranteed). It also implicitly treats citations as exchangeable and independent, which may not hold when sources are redundant or correlated.

\noindent\textbf{Qualitative Aggregation:} In addition to the numeric score, an LLM aggregator synthesizes a qualitative verdict from the per-citation results (see Algorithm~\ref{alg:judge_citation}, line 19). This thesis uses only the numeric aggregate scores for quantitative analysis.

\textbf{Configuration:} GPT-4.1 (or GPT-5-mini for cost reduction in GT Synth), T=0 for reproducibility.

\noindent\textbf{Prompt Variants}
\begin{enumerate}[noitemsep]
    \item \textbf{\PromptBaseline} (1500 max output tokens): Direct evaluation without scaffolding
    \item \textbf{\PromptMechanistic} (1500 max output tokens): Bradford Hill-aligned framework
    \item \textbf{\PromptCoT} (10000 max output tokens): Chain-of-Thought prompting with explicit step-by-step reasoning
    \item \textbf{\PromptMechanisticLit} (1500 max output tokens): Mechanistic prompt enhanced with explicit literature grounding requirements
\end{enumerate}
Full prompt texts are provided in Appendix~\ref{sec:citation_prompts}.

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:judge_citation}). \textbf{Fetcher algorithm/config:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:citation_fetcher}).

\noindent\textbf{Retrieval Mechanism}

\textbf{Step 1 (Search):} Brave Search is used to obtain up to 5 candidate citation URLs per edge, optionally filtered by a trusted-domain allowlist (Algorithm~\ref{alg:citation_search_brave}).

\textbf{Step 2 (Fetch):} For each URL, full text is fetched using the citation fetcher. In the experiments reported in this thesis, fetching was run in \textbf{ContentScraper-only} mode (BeautifulSoup-based fetching with PDF-capable extraction). See Appendix~\ref{alg:citation_fetcher} for the full fetcher pipeline and configuration details.

\textbf{Retrieval policy (compact summary).}
\begin{itemize}[noitemsep]
    \item \textbf{Domain filtering (search):} Citation URLs are obtained via Brave Search and filtered with a trusted-domain allowlist (up to 5 URLs retained per edge; Appendix~\ref{alg:citation_search_brave}).
    \item \textbf{Query construction:} For each edge, the search query concatenates the \texttt{source}, \texttt{relationship}, and \texttt{target} variables with the generated causal narrative/claim text; queries are truncated to Brave API limits (50 words, 400 characters).
    \item \textbf{Paywalls / partial text:} Full-text fetching uses ContentScraper with local PDF extraction; sources that fail to fetch or yield short/error content are discarded. If no valid full text can be fetched, the edge is assigned a \texttt{NO\_CITATION} outcome for citation-based judging.
\end{itemize}

\noindent\textbf{Retrieval Strategy: Generate-then-Search}
\label{sec:retrieval_strategy}

The Citation Judge follows a \textbf{generate-then-search} paradigm: the generator produces edges without retrieval constraints, and the judge subsequently searches for supporting literature. This decouples generation recall from retrieval coverage---the generator leverages its full parametric knowledge, while retrieval serves as post-hoc validation rather than a constraint on generation. See Section~\ref{sec:hybrid_generate_then_search} for motivation and limitations of this approach.

\label{sec:citation_search}
%------------------------------------------------------------------------------

\textbf{Input:} An edge claim (source variable, relationship type, target variable, and causal narrative), plus an optional trusted-domain allowlist and a Brave Search API key.

\textbf{Process:} The citation search component issues a web search query for each edge to obtain candidate citation URLs. Results are optionally filtered by a trusted-domain allowlist (e.g., academic/government domains) to bias toward credible sources. In this codebase, Brave search is used during citation filling when no usable citations are returned directly by an LLM (see Algorithm~\ref{alg:citation_search_brave}).

\section{Corrector}
\label{sec:corrector}
%------------------------------------------------------------------------------

\subsection{Design rationale: LLM-as-a-Corrector}
The corrector is implemented as a post-hoc remediation stage conditioned on judge feedback, allowing detection and remediation to be measured separately~\citep{dhuliawala2024chain, shinn2024reflexion}.

In this paragraph, we motivate how prior judge--corrector and iterative refinement frameworks inform the design of the corrector component implemented in this thesis. Motivated by these judge-then-correct frameworks~\citep{dhuliawala2024chain, shinn2024reflexion, madaan2023selfrefineiterativerefinementselffeedback}, we implement the corrector as a post-hoc remediation phase that is explicitly conditioned on judge feedback: candidate edges are selected from a Neo4j session based on low judge verdicts or low aggregate scores, and the corrector receives the edge \((A \rightarrow B)\), its current relationship type and motivation (causal narrative), and the judge's critique (verdict + message). Crucially, we explicitly separate judging and correction into distinct phases, rather than having a single model perform both tasks simultaneously. This separation follows the principle that task decomposition improves LLM performance on complex reasoning tasks~\citep{zhou2023leasttomostpromptingenablescomplex}, and allows us to measure detection and remediation performance independently---an important methodological requirement when evaluating whether hallucinations are being correctly identified versus successfully repaired. The corrector then executes one of a small set of auditable actions---either \textit{revise} the motivation while preserving the edge type, or \textit{change\_type} by switching the relationship label (e.g., \texttt{POSITIVE}/\texttt{NEGATIVE}$\leftrightarrow$\texttt{NONE}) while providing a new motivation---mirroring the ``generate then refine'' pattern in Self-Refine~\citep{madaan2023selfrefineiterativerefinementselffeedback} and the final correction step in CoVe~\citep{dhuliawala2024chain} while keeping the action space constrained to reduce uncontrolled edits. To mitigate the risk of introducing new errors, we optionally re-run the judge after corrections to re-score the updated edge set, closing a lightweight verify--correct loop. Unlike Reflexion~\citep{shinn2024reflexion}, we do not maintain cross-run memory; instead, correction decisions are logged back into the graph (e.g., \texttt{corrected}, \texttt{correction\_action}, \texttt{corrector\_message}) for reproducibility and downstream analysis. Full algorithmic details and the exact prompt variants used for the corrector are provided in Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:corrector}) and Appendix~\ref{sec:corrector_prompts}.

\subsection{Corrector implementation}
\textbf{Input:} Variables, relationship type, causal narrative, judgement from LLM-as-a-judge.

\textbf{Process:} Changes an edge by (see Appendix~\ref{alg:corrector} for algorithmic details):
\begin{itemize}[noitemsep]
    \item \textbf{a) Changing relationship type:} e.g., \texttt{None}$\rightarrow$\texttt{Positive}, \texttt{Negative}$\rightarrow$\texttt{None}
    \item \textbf{b) Revising motivation:} Rewriting causal narrative with improved reasoning/evidence
\end{itemize}

\textbf{Configuration:} GPT-4.1, T=0.7 for exploration~\citep{madaan2023selfrefineiterativerefinementselffeedback}. Full prompt variants (Baseline, CoT, Mechanistic) are provided in Appendix~\ref{sec:corrector_prompts}.

\noindent\textbf{Direction Correction Mechanism}
Because all pairs are evaluated bidirectionally ($A \rightarrow B$ and $B \rightarrow A$), direction errors are corrected via type changes:

\textbf{Example:} If $A \rightarrow B$ is erroneous (should be $B \rightarrow A$):
$A \xrightarrow{\texttt{NONE}} B$ (remove wrong) + $B \xrightarrow{\texttt{POS}} A$ (add correct)

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:corrector}). \textbf{Input parameters (prompts):} Appendix~\ref{sec:corrector_prompts}.

\section{Deep Research System}
\label{sec:deep_research_system}
%------------------------------------------------------------------------------

The Deep Research (DR) system is a multi-agent pipeline that iteratively searches scientific literature for evidence supporting or refuting causal relationships.

\subsection{Design rationale: Deep Research}
Deep Research is designed as a multi-agent, test-time compute pipeline for external evidence validation of edge claims. This section motivates the key design choices (decomposition, parallel search, reranking, and quoting) in relation to prior multi-agent and verification patterns.

In this subsection, we motivate how the multi-agent and test-time compute literature informs the Deep Research design choices evaluated in this thesis. The Deep Research system evaluated here is motivated by several recurring principles in the LLM multi-agent design literature. First, it uses iterative refinement to improve search behaviour over time, in the spirit of self-improvement loops such as Self-Refine~\citep{madaan2023selfrefineiterativerefinementselffeedback}. Second, it decomposes an edge claim into multiple independent search directions---including a verbatim query of the causal claim---and executes these directions in parallel, consistent with claim-decomposition patterns (e.g., CoVe)~\citep{dhuliawala2024chain} and compute-scaling strategies that benefit from parallel exploration~\citep{snell2024scalingllmtesttimecompute}. Third, it incorporates an explicit reranking step, which is common in literature search and retrieval systems and benefits from strong embedding models~\citep{muennighoff2023mteb, qwen3embedding2025}. In our implementation, we initially operate over Brave Search result snippets as lightweight evidence proxies---leveraging the provider's built-in retrieval and ranking via the Brave Search API~\citep{bravesearchapi}---and then perform full-text article fetching only for the highest-rated candidates most likely to contain direct causal evidence. Fourth, it adopts an orchestrated agent architecture with judge/corrector style control flow, implemented using typed agent tooling (PydanticAI)~\citep{pydanticai2024} and aligned with broader test-time compute perspectives~\citep{snell2024scalingllmtesttimecompute}. Finally, it requires explicit passage quoting to support evidence claims, in line with the SAFE framework, which has been shown to reduce hallucinations in retrieval-augmented settings~\citep{batista2025safeimprovingllmsystems}. Collectively, these choices prioritise breadth over minimality, maximizing the probability of finding direct causal evidence and enabling an initial test of whether automated literature search merits further investigation for CLD validation. Full system architecture and algorithmic details are described in Section~\ref{sec:deep_research_system}.

\subsection{Deep Research implementation}

\textbf{Input:} Causal claim (source variable, target variable, relationship type, causal motivation/narrative).

\textbf{Process:} Multi-agent literature search pipeline with iterative refinement (see Appendix~\ref{alg:deep_research} for algorithmic details):
\begin{itemize}[noitemsep]
    \item \textbf{Hypothesis evaluation:} Produces a focused search plan (3--4 queries) plus keywords and confounders; additionally inserts the \emph{verbatim claim} as a search query.
    \item \textbf{Parallel web search:} Runs the queries in parallel; within each query thread, the search agent iteratively calls a web-search tool with a hard search budget (max 5 searches per query thread). Retrieval uses Brave Search with a trusted-domain priority list and query augmentation (appending ``scientific study research evidence'').
    \item \textbf{Evidence scoring:} Scores each retrieved snippet/source on \texttt{relevance\_score} and \texttt{quality\_score} (1--10) with brief methodological justification.
    \item \textbf{Article selection \& full-text fetch:} Selects up to 2--3 candidate articles likely to contain direct causal evidence and fetches full text via HTML parsing (BeautifulSoup), truncating to a fixed length cap to avoid token overload.
    \item \textbf{Direct causal evidence detection:} Applies strict criteria for \emph{direct} causal support (e.g., RCTs/experiments, natural experiments, and meta-analyses/systematic reviews confirming causality); requires a verbatim quoted passage from the source.
    \item \textbf{Judgement, refinement, synthesis:} Judges aggregate support (and can propose a modified claim for a subsequent iteration), then synthesizes the final structured verdict.
\end{itemize}

\begin{sloppypar}
\textbf{Output:} Final verdict (\texttt{supported}/\texttt{partially\_supported}/\texttt{unsupported}/\texttt{invalid}), confidence score (1--10), {\small\texttt{direct\_causal\_found}} flag, strongest-evidence fields ({\small\texttt{strongest\_causal\_evidence\_url}, \texttt{\dots\_passage}, \texttt{\dots\_study\_type}, \texttt{\dots\_confidence}}), and a list of retrieved sources (\texttt{evidence\_urls}).
\end{sloppypar}

\noindent\textbf{Multi-Agent Architecture}

The system is implemented using the PydanticAI framework~\cite{pydanticai2024} with typed agent definitions and structured outputs. Seven primary LLM agents are coordinated by a Python orchestrator class in a multi-iteration pipeline (see Appendix~\ref{alg:deep_research} for algorithmic details); the codebase also defines an optional history summariser for token-budget management. The full multi-agent pipeline is documented in Table~\ref{tab:dr_agents} in Appendix~\ref{sec:dr_agents_appendix}.

\textbf{Models:} The Deep Research system uses a two-tier model architecture:
\begin{itemize}[noitemsep]
    \item \textbf{Heavy model (default: GPT-5):} Used for complex reasoning tasks---hypothesis evaluation, article selection, direct causal evidence detection, evidence judgement, and verdict synthesis.
    \item \textbf{Light model (default: GPT-5-mini):} Used for high-volume tasks---iterative web search and evidence scoring (and optional history summarization).
\end{itemize}

\textbf{Algorithm reference:} Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:deep_research}). \textbf{Agent components:} Appendix~\ref{sec:dr_agents_appendix} (Table~\ref{tab:dr_agents}). \textbf{Input parameters (configuration):} Appendix~\ref{sec:rq3_execution} (Table~\ref{tab:rq3_config}).

\noindent\textbf{Early Stopping Criteria}

The system terminates early when any of the following conditions are met:
\begin{itemize}[noitemsep]
    \item \textbf{Strong evidence found:} Direct causal evidence detected AND $\geq$3 high-quality sources (relevance $\geq 8$, quality $\geq 7$)
    \item \textbf{High confidence support:} Judgement supported with confidence $\geq 8$
    \item \textbf{Time limit:} 900 seconds (15 minutes) elapsed
    \item \textbf{Max iterations:} Configured iteration limit reached
\end{itemize}

\section{Evaluation Datasets (GT Lit, LLM Predictions, GT Synth)}
\label{sec:evaluation_datasets}

Across experiments we distinguish between (i) \textbf{ground-truth datasets} that define evaluation labels and (ii) \textbf{prediction artefacts} produced by the model that are scored against those labels.

\noindent\textbf{Ground truth datasets.}
\begin{itemize}[noitemsep]
    \item \textbf{GT Lit (literature ground truth):} The published CLDs (nodes and edges) extracted from peer-reviewed sources (Appendix~\ref{sec:data_availability}, Table~\ref{tab:gt_files}). For each domain, GT Lit defines the validation node set \(V\) and the validation edge labels used for scoring (see edge definition below). In GT Lit experiments, hallucinations are operationalised as FP/FN relative to this literature CLD.
    \item \textbf{GT Synth (synthetic corruption ground truth):} A controlled dataset constructed by taking an LLM Prediction edge table produced by Phase 1: Generation (Section~\ref{sec:generator}; Figure~\ref{fig:cld_pipeline}) and applying the Corruptor (Section~\ref{sec:corruptor}) to introduce known errors at a fixed corruption rate. As in all edge-level experiments, the node set is fixed to the validation node set \(V\), so corruption is defined over the same ordered-edge universe. Ground truth is the per-edge \texttt{corrupted} flag (rather than agreement with GT Lit). GT Synth is used to validate judge detection under fully known, injected error labels.
\end{itemize}

\noindent\textbf{Model predictions.}
\begin{itemize}[noitemsep]
    \item \textbf{LLM Predictions (generated edges over GT Lit nodes):} For each domain and run seed, we generate a CLD by fixing the node set to the GT Lit validation variables \(V\) and generating edges only. These generated edge tables are produced by the Phase 1: Generation pipeline (Section~\ref{sec:generator}; Figure~\ref{fig:cld_pipeline}) and are the primary predictions evaluated in RQ1--RQ3 (Figure~\ref{fig:experimental_pipeline_overview}). We compute accuracy/FP/FN metrics by comparing these predictions against either (i) GT Lit labels (deviation from literature) or (ii) GT Synth corruption labels when synthetic corruption is applied. Per-RQ output directories for these run artefacts (under \texttt{final\_runs/}) are listed in Appendix~\ref{sec:data_availability} (Table~\ref{tab:experiment_datasets}); file types and naming conventions are in Appendix~\ref{sec:output_artefacts} (Table~\ref{tab:output_files}).
\end{itemize}

\section{CLD Selection Rationale}
Ground truth CLDs were selected from peer-reviewed publications with explicitly defined causal structures (named variables, directed edges, polarities). The three CLDs span distinct subdomains within health---biopsychosocial health, public health behaviour, and healthcare systems---which aligns with the thesis's \textit{Mechanistic} (Bradford Hill--aligned) prompting framework for evaluating causal claims in health literature~\citep{shimonovich2020bradford}. CLD sizes range from 12 to 66 edges (validation sets: Social Norms 12, Depressive Symptoms 34, Emergency Department 66), providing variation in system complexity.

\textbf{Limitation:} All three CLDs fall within the health domain, limiting generalizability to other fields (e.g., economics, ecology, engineering). Additionally, these CLDs represent expert-hypothesized relationships rather than empirically validated causal effects---a common limitation in complex systems where controlled experiments are infeasible~\cite{uleman2024triangulation,crielaard2020socialnorms,smeekes2023emergency}. Evaluation therefore measures reproduction of published expert models, which may or may not be causally correct.

\textbf{Construct validity supplement:} To address the limitation that health CLDs reflect expert-hypothesised rather than empirically established causality, we include three physics-based CLDs (Thermostat Heating, RC Circuit, Water Tank; Section~\ref{sec:physics_validation}) as supplementary validation cases where causal relationships are unambiguously grounded in mathematical laws. Unlike the health domain CLDs, these systems offer \emph{known} causal structure derivable from first principles---if the judge rejects edges in these ``easy'' cases, it would indicate fundamental judge failure rather than domain complexity. This design provides a lower bound on expected judge performance and helps disentangle judge functioning from the inherent causal ambiguity present in complex socio-biomedical systems. Due to cost constraints, these physics CLDs were not included in the main RQ1--RQ3 experiments but serve as auxiliary validation benchmarks.

\section{Task Definition}
\label{sec:task_definition}
\label{sec:problem_setup} % Legacy label for backwards compatibility
\label{sec:task_cld_hallucination_detection}
\label{sec:task_cld_generation}

The end-to-end system produces Causal Loop Diagrams (CLDs)---directed graphs where nodes represent system variables and edges represent causal relationships with polarity (\texttt{POSITIVE}, \texttt{NEGATIVE}, or \texttt{NONE}) and mechanistic explanations. However, the primary task evaluated in this thesis is detecting and mitigating hallucinations in CLD edge predictions produced by an LLM generator under a fixed variable set.

Throughout RQ1--RQ3, we operate on ordered \emph{edges} \((A,B)\) over a fixed node set \(V\) obtained from the ground-truth literature CLDs. For each edge, the generator outputs a relationship label in \{\texttt{POSITIVE}, \texttt{NEGATIVE}, \texttt{NONE}\} plus a short mechanistic narrative (and, where applicable, citations). Hallucination detection assigns each edge a binary label (hallucinated vs.\ non-hallucinated) under a specified ground-truth construct (GT Lit vs.\ GT Synth), and mitigation mechanisms (corrector / Deep Research) attempt to improve alignment.

Generation is treated as a \emph{given input process}: we fix the validation node set \(V\) to the GT Lit variables and evaluate downstream verification/remediation methods on the resulting edge tables, isolating hallucination detection/mitigation performance from confounds due to differing node sets. Full generation details are in Appendix~\ref{sec:algorithms} (Algorithm~\ref{alg:cld_generation}); input/output data specifications are in Appendix~\ref{sec:data_availability}.

\section{Hallucination Operationalisation}
\label{sec:hallucination_operationalisation}
\label{sec:hallucination_definition} % Legacy label for backwards compatibility
%------------------------------------------------------------------------------

In this thesis, hallucinations manifest as incorrectness in causal links: erroneous absence (FN) or presence (FP) of links, wrong direction, or wrong causal narrative. We operationalise hallucination under two complementary ground-truth constructs, summarised in Table~\ref{tab:tp_fp_fn_notation}:

\begin{itemize}[noitemsep,topsep=0.3em]
    \item \textbf{GT Lit} (literature ground truth): Hallucination is defined as FP or FN with respect to a peer-reviewed expert CLD. This evaluates alignment with domain expert consensus.
    \item \textbf{GT Synth} (synthetic ground truth): Hallucination is defined as edges marked \texttt{corrupted=True} by an LLM corruptor that introduces controlled perturbations at a 30\% rate. This provides fully known error labels for controlled evaluation, connecting to broader hallucination benchmarks such as HaluEval~\cite{li2023halueval}.
\end{itemize}

\noindent Results across GT Lit and GT Synth are complementary: GT Synth validates controlled detection of induced errors, while GT Lit evaluates alignment with expert reference CLDs in domain-specific settings. The corruptor component is described in Section~\ref{sec:corruptor}; the full algorithm is in Appendix~\ref{sec:algorithms}.

\noindent\textbf{Design Rationale and Unit of Inference}
\label{sec:block_design}
\begin{itemize}[noitemsep]
    \item \textbf{GT Lit experiments:} CLD generation varies (seeds 10, 20, 30) $\rightarrow$ tests judge generalisation across CLD instances
    \item \textbf{GT Synth experiments:} Corruption varies (seeds 1, 2, 3), base CLD fixed $\rightarrow$ isolates corruption detection ability
    \item \textbf{Seed separation:} Methodological independence between paradigms (10/20/30 vs 1/2/3)
\end{itemize}

\textbf{Controlling for confounds.} The seed structure explicitly controls for potential confounds. In GT Synth experiments, fixing the base CLD while varying only the corruption seed ensures that performance differences reflect the judge's ability to detect different corruption patterns---not differences in underlying CLD structure. In GT Lit experiments, CLD structure variation is intentional: we deliberately test whether the judge generalises across different valid CLD realizations. The seed separation (10/20/30 for generation vs. 1/2/3 for corruption) maintains methodological independence.

Experiments use a \textbf{repeated-measures design} with 9 independent blocks (3 CLDs $\times$ 3 runs; seeds 10, 20, 30 for generation; 1, 2, 3 for corruption). Each block receives all treatment levels (prompt variants), enabling within-block comparisons. This structure:

\begin{itemize}[noitemsep]
    \item \textbf{Controls for CLD-level variance:} Performance is confounded by domain difficulty (Depressive Symptoms vs.\ Social Norms vs.\ Emergency Department); blocking isolates treatment effects.
    \item \textbf{Controls for run-to-run variance:} Different seeds produce different CLD instances; blocking treats each (CLD, run) pair as a subject.
    \item \textbf{Enables within-subject analysis:} Prompt variants or methods are compared within the same block, increasing statistical power.
\end{itemize}

\textbf{Unit of inference:} The block-level (CLD$\times$run) summary statistic is the unit of analysis for meta-level statistical tests. Where multiple prompt variants exist within a block, prompt is treated as a within-block factor (paired comparisons); for pooled summaries we use the block mean. This yields $N=9$ independent observations for hypothesis testing.

\section{Metrics}

\noindent\textbf{Definitions and Output Metrics}
\label{sec:metrics_definitions}
%------------------------------------------------------------------------------

This section consolidates all metrics used across experiments.

\paragraph{Classification Metrics (Judge Evaluation; RQ1a).}
\begin{itemize}[noitemsep]
    \item \textbf{AUC-ROC:} Area under the ROC curve (judge score vs.\ hallucination label). Baseline: AUC = 0.5 (random classification).
    \item \textbf{Precision:}
    \begin{equation}
        \mathrm{Precision} = \frac{TP}{TP + FP}
    \end{equation}
    \item \textbf{Recall:}
    \begin{equation}
        \mathrm{Recall} = \frac{TP}{TP + FN}
    \end{equation}
    \item \textbf{F1:}
    \begin{equation}
        \mathrm{F1} = \frac{2 \cdot TP}{2 \cdot TP + FP + FN}
    \end{equation}
    \item \textbf{Correlation ($r$):} Point-biserial correlation between judge score $s$ and binary hallucination label $y\in\{0,1\}$:
    \begin{equation}
        r_{pb}=\frac{\bar{s}_1-\bar{s}_0}{s_s}\sqrt{pq}
    \end{equation}
    where $\bar{s}_1$ and $\bar{s}_0$ are mean scores for the $y{=}1$ and $y{=}0$ groups, $s_s$ is the sample standard deviation of scores, and $p=\Pr(y{=}1)$, $q=\Pr(y{=}0)$.
    \item \textbf{Classification threshold:} Judge score $\leq 0.5$ predicts hallucination.
    \item \textbf{Confusion matrix terms:} $TP=\#\{y{=}1,\hat{y}{=}1\}$, $FP=\#\{y{=}0,\hat{y}{=}1\}$, $FN=\#\{y{=}1,\hat{y}{=}0\}$, $TN=\#\{y{=}0,\hat{y}{=}0\}$.
\end{itemize}

\noindent\textbf{Threshold justification.} Scores are ordinal and discrete by design (0.0/0.5/1.0): \textbf{0.0} indicates an explicit error, \textbf{0.5} indicates a detected partial flaw/uncertainty, and \textbf{1.0} indicates full correctness/support. Under our operational definition of hallucination as \emph{edge-level incorrectness}, any detected error (i.e., \texttt{INCORRECT} or \texttt{PARTIALLY\_CORRECT} / \texttt{NOT\_SUPPORTED} or \texttt{PARTIALLY\_SUPPORTED}) implies the edge should be flagged as hallucinated, which yields the natural cutpoint \(\le 0.5\). We additionally report ROC curves from a discrete threshold sweep over the only meaningful operating points induced by these three score levels (Appendix~\ref{sec:appendix_roc_curves}; Figures~\ref{fig:rq1a_gt_correctness_roc}--\ref{fig:rq1a_gt_citation_roc}, \ref{fig:rq1a_corr_correctness_roc}--\ref{fig:rq1a_corr_citation_roc}); for judges that exceed chance discrimination (AUC$>0.5$), the \(\le 0.5\) operating point corresponds to the intended ``any detected error'' decision rule used throughout the main thresholded Precision/Recall/F1 analyses.

\paragraph{Judge Output Scores.}
\begin{itemize}[noitemsep]
    \item \textbf{Correctness Judge (per-edge):} 0.0 (INCORRECT), 0.5 (PARTIALLY\_CORRECT), 1.0 (CORRECT)
    \item \textbf{Citation Judge (per-citation):} 0.0 (NOT\_SUPPORTED), 0.5 (PARTIALLY\_SUPPORTED), 1.0 (SUPPORTED)
    \item \textbf{Citation Judge (per-edge):} The mean of per-edge aggregate scores. For a single edge with $C$ retrieved citations, the edge-level score is:
    \begin{equation}
        \text{score}_{\text{edge}} = \frac{1}{C}\sum_{c=1}^{C} \text{verdict}_c
    \end{equation}
    where $\text{verdict}_c \in \{0.0, 0.5, 1.0\}$ corresponds to \textsc{Contradicted}/\textsc{Unaddressed}, \textsc{Partially Supported}, and \textsc{Supported} respectively.
\end{itemize}

\paragraph{Correction Metrics (RQ1b).}
\begin{itemize}[noitemsep]
    \item \textbf{$\Delta$F1, $\Delta$Precision, $\Delta$Recall:} Change from pre- to post-correction w.r.t.\ ground truth
    \item \textbf{$\Delta$Judge Score:} $\text{mean}(\text{corrected edges}) - \text{mean}(\text{original edges})$
\end{itemize}

\paragraph{UQ Metrics (RQ2).}\label{sec:uq_metrics_capping} Context-insensitive metrics captured during generation:
\begin{itemize}[noitemsep]
    \item \textbf{Perplexity:} Average token-level uncertainty (capped NLL)
    \item \textbf{Min Probability:} Confidence floor---minimum token probability
    \item \textbf{Max Window Entropy:} Highest-uncertainty region (5-token sliding window)
    \item \textbf{Cosine Similarity:} Semantic alignment between narrative and citations (citation experiments only)
\end{itemize}

\noindent\textbf{Perplexity computation.} Two-stage capping improves robustness and avoids numerical instability: (1) individual token NLL values are capped at 20.0 before averaging,
\[
\mathrm{nll}_i=\min\!\left(-\log P(x_i),\,20.0\right),
\]
preventing single outlier tokens (\(P<2\times 10^{-9}\)) from dominating; (2) the average NLL is capped at 10.0, and perplexity is computed as:
\[
\mathrm{PPL} = \exp\!\left(\min\!\left(\frac{1}{n}\sum_{i=1}^{n}\mathrm{nll}_i,\;10.0\right)\right),
\]
bounding perplexity at \(e^{10}\approx 22{,}026\) to prevent extreme values from overwhelming comparisons.

\noindent\textbf{Min Probability.} The minimum token probability across the entire generated sequence:
\[
P_{\min} = \min_{i \in \{1,\ldots,n\}} P(x_i),
\]
representing the confidence floor of the single least-confident token prediction. Low minimum probability indicates at least one token was generated with high uncertainty, which we treat as a candidate indicator of localized uncertainty. This metric is complementary to perplexity: while perplexity captures average uncertainty, min probability captures worst-case uncertainty.

\noindent\textbf{Max Window Entropy.} Two-step aggregation detects localized uncertainty spikes: (1) at each token position, compute entropy over top-\(k{=}5\) alternatives returned by the API,
\[
H_k(t)=-\sum_{j=1}^{k}\tilde{p}_j(t)\log \tilde{p}_j(t),
\qquad
\tilde{p}_j(t)=\mathrm{softmax}(\mathrm{logprob}_j(t));
\]
(2) apply a sliding window of size \(w{=}5\) to compute rolling averages (via \texttt{np.convolve}), then return the maximum:
\[
H_{\max\text{-}win}=\max_{i}\frac{1}{w}\sum_{t=i}^{i+w-1} H_k(t).
\]
This identifies the highest-uncertainty region in the generated text.

\noindent\textbf{Cosine Similarity.}
\label{sec:uq_cossim}
Embeddings are computed locally using \texttt{all-mpnet-base-v2}~\cite{muennighoff2023mteb} (768-dim, 384-token limit). Citation texts are chunked with an adaptive window: \texttt{chunk\_size} \(=\max(256,\min(4000,|\text{motiv.}|))\) characters, 20\% overlap, de-duplicated. This adaptive sizing ensures chunks remain within the model's 384-token context (motivations average 56 tokens, max 137; implied chunks 57--176 tokens). For each edge, \(\mathrm{sim}=\max_c \cos(\mathbf{e}_{\mathrm{narr}},\mathbf{e}_c)\) over all citation chunks. Available only for citation experiments.

\noindent\textbf{Model Selection.} We selected \texttt{all-mpnet-base-v2} based on benchmarking against Qwen3-Embedding-8B (Appendix~\ref{sec:embedding_benchmark}; Tables~\ref{tab:embed_benchmark} and~\ref{tab:mteb_comparison}): 22$\times$ faster (3.0 vs.\ 67.3 ms/doc) in our setup. Because cosine similarity scoring is throughput-bound in our pipeline, we prioritise latency; published MTEB results are included in Appendix~\ref{sec:embedding_benchmark} for context only (not as a direct cross-model comparison).

\paragraph{Deep Research Metrics (RQ3).}
\begin{itemize}[noitemsep]
    \item \textbf{Detection Rate:} Fraction of edges with \texttt{direct\_causal\_found=True}. For an edge class \(A\in\{\text{TP},\text{FP},\text{FN}\}\), we define
    \[
    \text{DR}_{A}=\frac{1}{|E_A|}\sum_{e\in E_A}\mathbb{I}\{\texttt{direct\_causal\_found}(e)=\texttt{True}\},
    \]
    where \(E_A\) is the set of edges in class \(A\).
    \item \textbf{Pairwise DR Gaps (pp):} $\text{DR}_{A} - \text{DR}_{B}$ for $A,B\in\{\text{TP},\text{FP},\text{FN}\}$ (reported for TP--FP, TP--FN, FP--FN). As a practical heuristic, $>20$pp indicates meaningful discrimination.
    \item \textbf{Confidence Score:} Deep Research self-assessed confidence (1--10; reported as mean by class and CLD).
    \item \textbf{Uncertainty for proportions:} Wilson score 95\% confidence intervals for detection rates (see Appendix~\ref{app:statistical_procedures_reference}).
    \item \textbf{Discrimination tests:} Fisher's exact test for differences in detection rates (with Bonferroni-adjusted p-values for the TP--FP / TP--FN / FP--FN family; see Appendix~\ref{app:statistical_procedures_reference}).
    \item \textbf{Effect sizes (RQ3):} Cohen's $h$ for detection-rate differences; odds ratio (OR) with 95\% CI from the $2\times2$ contingency table.
\end{itemize}

\paragraph{Human Validation Metrics (RQ1a Validation, RQ3).}
\begin{itemize}[noitemsep]
    \item \textbf{Cohen's $\kappa$ (kappa):} Chance-corrected inter-rater agreement:
    \begin{equation}
        \kappa = \frac{p_o - p_e}{1 - p_e}
    \end{equation}
    where $p_o$ is observed agreement and $p_e$ is expected agreement by chance. Interpretation (Landis \& Koch~\cite{landis1977measurement}): $<$0.20 slight, 0.21--0.40 fair, 0.41--0.60 moderate, 0.61--0.80 substantial, $>$0.80 almost perfect.
    \item \textbf{Agreement Rate:} Exact match percentage between raters (before chance correction).
    \item \textbf{Pearson $r$:} Correlation between continuous judge scores and human ratings; used to assess score-level (not categorical) alignment.
    \item \textbf{ICC (Intraclass Correlation Coefficient):} For continuous applicability scores (RQ3 inter-rater check), ICC(2,1) (two-way random effects, absolute agreement, single measures):
    \begin{equation}
        \text{ICC} = \frac{\sigma^2_{\text{between}}}{\sigma^2_{\text{between}} + \sigma^2_{\text{within}}}
    \end{equation}
    Interpretation~\cite{koo2016guideline}: $<$0.50 poor, 0.50--0.75 moderate, 0.75--0.90 good, $>$0.90 excellent.
\end{itemize}

\paragraph{RQ3 Human Validation Metrics (Applicability-Based Calibration).}
\begin{itemize}[noitemsep]
    \item \textbf{Applicability Score:} Human-assigned continuous score $\in[0,1]$ indicating how well retrieved evidence matches the exact edge claim. Rubric: 1.0 = exact match; 0.8--0.9 = different operationalisations; $\approx$0.7 = partial claim; $\approx$0.6 = proxy constructs; $\leq$0.5 = weak/non-causal evidence.
    \item \textbf{Coverage:} Fraction of edges with applicability $\geq t$ for threshold $t$:
    \begin{equation}
        \text{Coverage}(t) = \frac{|\{e : \text{applicability}(e) \geq t\}|}{|E|}
    \end{equation}
    \item \textbf{Correct-causal Rate:} Fraction of passing edges labelled \texttt{causal} by human validator:
    \begin{equation}
        \text{Correct-causal}(t) = \frac{|\{e : \text{applicability}(e) \geq t \land \text{verdict}(e) = \texttt{causal}\}|}{|\{e : \text{applicability}(e) \geq t\}|}
    \end{equation}
\end{itemize}

\paragraph{Aggregation Methods (Generator Evaluation).}
\begin{itemize}[noitemsep]
    \item \textbf{Micro-average:} Pooled TP/FP/FN across all CLDs before computing Precision/Recall/F1. Gives equal weight to each edge.
    \item \textbf{Macro-average:} Compute Precision/Recall/F1 per CLD, then average. Gives equal weight to each CLD regardless of size.
    \item \textbf{Graph Density:} Fraction of possible edges present in the CLD:
    \begin{equation}
        \text{Density} = \frac{|E|}{|V| \times (|V| - 1)}
    \end{equation}
    where $|E|$ is edge count and $|V|$ is node count. Used for random baseline contextualisation.
\end{itemize}

\paragraph{Accuracy (TruthfulQA Verification).}
\begin{equation}
    \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
\end{equation}
Used to verify judge implementation on the TruthfulQA benchmark before CLD-specific experiments.

\paragraph{Specificity (TruthfulQA Verification).}
Specificity (true negative rate) measures how well the judge avoids false hallucination flags on truthful answers:
\begin{equation}
    \text{Specificity} = \frac{TN}{TN + FP}.
\end{equation}

\paragraph{Citation Retrieval Metrics (Validation; Citation Judge).}
Because citation-based judging depends on successful full-text fetching, we report retrieval and conditional approval metrics:
\begin{itemize}[noitemsep]
    \item \textbf{Retrieval success rate (fetch coverage):} fraction of edges with at least one successfully fetched citation text:
    \begin{equation}
        \text{RetrievalSuccess} = \frac{|\{e : C_e \ge 1\}|}{|E|}
    \end{equation}
    where $C_e$ is the number of usable fetched citations for edge $e$.
    \item \textbf{NO\_CITATION rate:} fraction of edges where no citation text could be fetched ($C_e = 0$), i.e., $1-\text{RetrievalSuccess}$.
    \item \textbf{Score difference (fetcher comparison):} difference in average citation-judge score between two fetchers/configurations (e.g., ContentScraper minus Jina AI):
    \begin{equation}
        \Delta \text{Score} = \overline{s}_{A} - \overline{s}_{B}.
    \end{equation}
    \item \textbf{Approval rate (overall):} fraction of edges with citation-judge score above the acceptance threshold (as defined in the corresponding experiment).
    \item \textbf{Approval rate (conditional on retrieval):} approval restricted to retrieved edges ($C_e \ge 1$), used to separate infrastructure failures from validation failures.
\end{itemize}

\paragraph{RQ2 Model Interpretation Metrics (UQ ensembles).}
To analyse which UQ features drive classifier performance, we use:
\begin{itemize}[noitemsep]
    \item \textbf{Recursive Feature Elimination (RFE) selection frequency:} fraction of cross-validation folds in which a feature is selected by RFE (reported as a stability diagnostic).
    \item \textbf{Permutation importance (AUC drop):} decrease in test AUC when a feature is randomly permuted (shuffled) while holding other features fixed; larger drops indicate greater reliance on that feature.
\end{itemize}

\paragraph{Cross-Domain Generalisation Gap (RQ2).}
When comparing in-distribution vs.\ leave-one-CLD-out evaluation, we report the AUC drop:
\begin{equation}
    \Delta \text{AUC} = \text{AUC}_{\text{in}} - \text{AUC}_{\text{out}}.
\end{equation}

\paragraph{Computational Efficiency Metrics (RQ3, Scaling, Parallelization).}
We report cost/latency metrics for selective deployment and parallel execution:
\begin{itemize}[noitemsep]
    \item \textbf{$\Delta$F1 per dollar:} improvement in expected F1 divided by total compute cost (often scaled as $\Delta$F1 per \$100 for readability).
    \item \textbf{Cost per +0.1 F1:} extrapolated dollars required for a +0.1 increase in expected F1 under a specified scaling model.
    \item \textbf{Wall-clock time:} elapsed runtime (seconds) for a fixed workload under a given worker count.
    \item \textbf{Speedup:} parallel speedup relative to single worker, $\text{Speedup} = T_1/T_W$.
    \item \textbf{Parallel efficiency:} speedup per worker, $\text{Efficiency} = (\text{Speedup}/W)\times 100\%$.
\end{itemize}

\section{Statistical Analysis}

\noindent\textbf{Non-Parametric Testing Framework (Main Results)}
\label{sec:nonparam_framework}
%------------------------------------------------------------------------------

For \textbf{prompt sensitivity} (RQ1a, RQ1b), we use non-parametric repeated-measures tests because the number of independent replicates is small ($n=9$ blocks) and distributional assumptions are difficult to verify. In addition, several primary outcomes are \textbf{bounded} (e.g., AUC $\in[0,1]$, Precision/Recall/F1 $\in[0,1]$) and judge scores are \textbf{discrete} (0.0/0.5/1.0), which can induce non-normality and ceiling/floor effects under small-$n$ aggregation; rank-based tests reduce sensitivity to these issues:
\begin{itemize}[noitemsep]
    \item \textbf{Friedman test} (see Appendix~\ref{app:statistical_procedures_reference}): Non-parametric equivalent of repeated-measures ANOVA; ranks observations within each block and tests whether rank sums differ across treatments.
    \item \textbf{Post-hoc Wilcoxon signed-rank tests} (see Appendix~\ref{app:statistical_procedures_reference}): Pairwise comparisons between specific prompts within matched blocks.
    \item \textbf{Effect size:} Kendall's $W$ ($<$0.1 negligible, 0.1--0.3 small, 0.3--0.5 medium, $\geq$0.5 large).
\end{itemize}

This framework is robust to small sample sizes, non-normality, and outliers. The trade-off is that it primarily answers \textit{whether prompts differ} (in a rank-based sense), but it does not yield the same kind of variance decomposition and sensitivity measures as parametric repeated-measures models.

\textbf{Sensitivity Analysis (Appendix~\ref{app:sensitivity_analysis}; Methods~\S\ref{sec:rq1a_sensitivity}).} For sensitivity-style interpretation (e.g., ``how much variability is explained by prompts''), we also report \textbf{Repeated-Measures ANOVA} (RM-ANOVA) with variance decomposition (e.g., $\eta^2_p$). The trade-off is the opposite of the non-parametric approach: RM-ANOVA is more interpretable for sensitivity, but it relies on stronger distributional assumptions that are hard to validate convincingly at $n=9$. We therefore treat RM-ANOVA as a \textit{secondary} sensitivity summary (reporting $F$, df, $p$, and $\eta^2_p$), and keep the non-parametric results as the primary inferential evidence for prompt differences.

\paragraph{RQ2 hypothesis tests (single-metric UQ detection).}
For each UQ metric, we compute a \textbf{block-level} AUC-ROC (blocks = CLD$\times$run, $n=9$) and test whether discrimination exceeds chance:
\begin{itemize}[noitemsep]
    \item \textbf{Primary test:} one-sample $t$-test on block-level AUCs vs.\ 0.5 (Appendix~\ref{app:statistical_procedures_reference}). $H_0:\mu_{\text{AUC}}=0.5$, $H_1:\mu_{\text{AUC}}\neq 0.5$.
    \item \textbf{Assumption check:} Shapiro--Wilk test on block-level AUCs (Appendix~\ref{app:statistical_procedures_reference}); as a robustness check we also report a one-sample Wilcoxon signed-rank test on $(\mathrm{AUC}-0.5)$ over blocks when distributional assumptions are questionable.
    \item \textbf{Distribution comparison:} Mann--Whitney U test (Appendix~\ref{app:statistical_procedures_reference}) compares hallucinated vs.\ correct edge distributions within each CLD; effect size reported as rank-biserial $r$.
    \item \textbf{Correlation aggregation:} Pearson $r$ (including point-biserial correlation for binary labels) is computed per experimental file and aggregated using Fisher $z$-transformation across files (Appendix~\ref{app:statistical_procedures_reference}).
\end{itemize}

\paragraph{RQ3 hypothesis tests (Deep Research discrimination).}
RQ3 compares \textbf{detection rates} (Found vs.\ Not Found for \texttt{direct\_causal\_found}) between edge classes:
\begin{itemize}[noitemsep]
    \item \textbf{Primary test:} Fisher's exact test on $2\times2$ contingency tables for TP--FP, TP--FN, and FP--FN (Appendix~\ref{app:statistical_procedures_reference}); p-values are Bonferroni-adjusted within this family.
    \item \textbf{Uncertainty:} Wilson score 95\% confidence intervals for detection-rate proportions.
    \item \textbf{Effect sizes:} Cohen's $h$ for proportion differences, and odds ratio (OR) with 95\% CI from the contingency table.
\end{itemize}

%------------------------------------------------------------------------------
\noindent\textbf{Multiple Comparison Corrections}
\label{sec:multiple_comparisons}
%------------------------------------------------------------------------------

Bonferroni corrections control family-wise error rate, grouped by research question (see Appendix~\ref{app:statistical_procedures_reference}):
\begin{itemize}[noitemsep]
    \item \textbf{RQ1a:} 4 omnibus Friedman tests (one per judge$\times$GT setting) $\rightarrow$ $\alpha_{\text{adj}} = 0.0125$; \emph{post-hoc} prompt comparisons within each setting: \textbf{Correctness Judge} uses $k=3$ prompts $\rightarrow$ 3 pairwise comparisons, $\alpha_{\text{adj}} = 0.0167$; \textbf{Citation Judge} uses $k=4$ prompts (including \textbf{GT Lit} and \textbf{GT Synth}) $\rightarrow$ 6 comparisons, $\alpha_{\text{adj}} = 0.0083$
    \item \textbf{RQ1b:} 2 omnibus Friedman tests $\rightarrow$ $\alpha_{\text{adj}} = 0.025$; post-hoc 3 pairs $\rightarrow$ $\alpha_{\text{adj}} = 0.0167$ (see Appendix~\ref{app:statistical_procedures_reference})
    \item \textbf{RQ2:} 4 single-metric tests $\rightarrow$ $\alpha_{\text{adj}} = 0.0125$
    \item \textbf{RQ3:} 3 Fisher's exact tests $\rightarrow$ $\alpha_{\text{adj}} = 0.017$ (see Appendix~\ref{app:statistical_procedures_reference})
\end{itemize}

\textbf{Scope of correction families.} Unless stated otherwise, we apply Bonferroni corrections \emph{within each research question} (RQ) and within the corresponding family of statistical tests listed above. For RQ1a and RQ1b prompt-sensitivity analyses, corrections apply to post-hoc prompt comparisons within each experiment/metric (e.g., a given judge$\times$GT setting and metric such as F1 or AUC). We do not apply a single global correction across all RQs because each RQ tests a distinct hypothesis and is reported as a separate confirmatory family.

\noindent\textbf{Uncertainty Reporting Rule}
\label{sec:uncertainty_rule}
%------------------------------------------------------------------------------

For repeated measurements (across CLDs, runs/seeds, or CV folds), we report \textbf{mean $\pm$ 95\% CI} using the $t$-distribution with $df = N-1$. This accounts for variance uncertainty in small samples (e.g., $N=3$ runs or $N=9$ blocks). For proportions (e.g., detection rates), we use Wilson score 95\% intervals.

Interpretation: Readers should interpret small-$N$ intervals ($N < 10$) as approximate rather than precise; confirmatory conclusions rely on block-based non-parametric tests (Friedman/Wilcoxon) rather than visual CI overlap. CV fold scores are not independent draws (folds share training data), so fold-based intervals should not be interpreted as strict confidence intervals.

\textbf{Statistical Power.} Given the small number of independent blocks ($N=9$), our main repeated-measures analyses have limited sensitivity to small effects; null results should therefore not be over-interpreted as evidence of no effect. We emphasise standardised effect sizes alongside $p$-values (Table~\ref{tab:effect_size_summary}, Results).

\section{Validity Considerations}
\label{sec:threats_to_validity}
%==============================================================================

Our data are highly structured: many edges come from the same generation scenario, and multiple prompt variants are evaluated within the same (CLD$\times$run) block. To mitigate pseudo-replication and leakage, we adopt block-aware design choices: (i) treating (CLD$\times$run) as the independent unit for prompt comparisons ($N=9$ blocks; Section~\ref{sec:block_design}); (ii) using group-aware cross-validation splits that keep entire blocks together (GroupKFold / GroupShuffleSplit; Section~\ref{sec:rq2_analysis}); and (iii) treating edge-level results as descriptive diagnostics rather than inferential claims.

A comprehensive discussion of validity threats---including construct validity (what ``hallucination'' measures in GT Lit vs.\ GT Synth), external validity (domain, model, and retrieval dependence), conclusion validity (statistical power and multiple comparisons), and reliability concerns (LLM stochasticity and judge biases)---is provided in Section~\ref{sec:discussion_limitations}.
