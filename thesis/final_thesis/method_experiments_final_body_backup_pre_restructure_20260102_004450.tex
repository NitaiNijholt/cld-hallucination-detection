\section{System Overview}
%==============================================================================

\label{sec:methods_system_overview}

Figure~\ref{fig:cld_pipeline} presents the complete CLD generation, judging, and correction pipeline. The system operates in three phases:

\begin{enumerate}[noitemsep]
    \item \textbf{Generation:} The LLM generator (GPT-4.1) constructs CLDs through iterative node and edge generation, capturing uncertainty quantification (UQ) metrics for downstream hallucination detection.
    \item \textbf{Judging:} An LLM judge evaluates each edge using either correctness-based reasoning assessment or citation-based verification, producing per-edge verdicts.
    \item \textbf{Correction:} An LLM corrector applies tool-based fixes to flagged edges, followed by re-judging to validate corrections.
\end{enumerate}

\section{Experimental Overview \& Definitions}

\subsection{Hallucination Definition}
\label{sec:hallucination_definition}

\subsubsection{Manifestations}
Hallucinations = \textbf{incorrectness in causal links}: erroneous \textit{absence} (FN) or \textit{presence} (FP) of links, wrong direction, or wrong causal narrative.

\subsubsection{Operationalization}
\begin{itemize}[noitemsep]
    \item \textbf{GT Lit:} CLD from peer-reviewed literature. \textbf{Hallucination = FP/FN} w.r.t. literature CLD.
    \item \textbf{GT Synth:} LLM-corrupted edges. \textbf{Hallucination = corrupted edges} (corrupted=True).
\end{itemize}

\subsubsection{Corruption Process (HaluEval-inspired~\cite{li2023halueval})}
The Corruptor introduces controlled errors to test judge detection (see Appendix~\ref{alg:corruption} for algorithmic details). Three corruption types with \textbf{rate=0.3}, balanced distribution:
\begin{enumerate}[noitemsep]
    \item \textbf{Motivation corruption:} Replaces valid explanations with plausible-but-flawed reasoning
    \item \textbf{Spurious edges:} Converts \texttt{NONE} $\rightarrow$ false positive links (\texttt{POSITIVE}/\texttt{NEGATIVE})
    \item \textbf{Polarity flips:} Inverts \texttt{POSITIVE} $\leftrightarrow$ \texttt{NEGATIVE}
\end{enumerate}

\textbf{Key Parameters (Corruptor):} \texttt{model=gpt-4.1}, \texttt{temp=0.7}, \texttt{top\_p=1}, \texttt{rate=0.3}

\subsection{Retrieval Strategy: Generate-then-Search}
\label{sec:retrieval_strategy}

Traditional Retrieval-Augmented Generation (RAG) systems follow a \textbf{search-then-generate} paradigm: first retrieve relevant documents from a corpus, then condition the language model's generation on the retrieved context~\cite{lewis2020rag}. While effective for factoid question answering, this approach faces critical limitations when applied to complex reasoning tasks such as causal loop diagram construction.

\subsubsection{The Overconstraining Problem}

Search-first approaches introduce a dependency on retrieval quality that can \textbf{overconstrain} the model's output:

\begin{itemize}[noitemsep]
    \item \textbf{Retrieval bottleneck:} If the retrieval system fails to surface relevant documents---due to indexing gaps, suboptimal query formulation, or domain vocabulary mismatch---the model cannot access valid knowledge even if it exists in its parametric memory. Generator ablations (although limited in scope and depth) support this: mandatory citation requirements reduced performance by 25\%, and overly restrictive grounding caused complete failure (F1=0.00; see Appendix~\ref{sec:ablation_edge}).
    \item \textbf{Corpus coverage limitations:} Scientific literature databases may lack coverage of interdisciplinary relationships, emerging hypotheses, or domain-specific mechanisms that are well-represented in LLM pretraining data but not yet indexed in targeted search corpora.
    \item \textbf{Query formulation paradox:} Constructing effective search queries requires knowing what causal relationships to look for---but in CLD generation, these relationships are precisely what the model is trying to discover. This creates a chicken-and-egg problem where retrieval cannot effectively guide generation.
\end{itemize}

\subsubsection{Generate-then-Search Approach}

We adopt a \textbf{generate-then-search} paradigm that decouples generation from retrieval:

\begin{enumerate}[noitemsep]
    \item \textbf{Unconstrained Generation:} The LLM generates candidate causal relationships using its full parametric knowledge, without retrieval constraints. This leverages the model's encoded information regarding the relationships between variables from pretraining.
    \item \textbf{Post-hoc Evidence Search:} Generated edges are subsequently validated by searching for supporting evidence (Citation Judge in RQ1a; Deep Research in RQ3). The search targets the \textit{generated} causal claim, enabling focused queries.
\end{enumerate}

This design treats retrieval as a post-hoc validation mechanism rather than a constraint on generation. 

\subsubsection{Trade-offs}

\textbf{Advantages:}
\begin{itemize}[noitemsep]
    \item Relationship level Recall (relationships being found) is increased by removing the constraint reduction on retrieved evidence against precision (relationships being correct).
    \item Avoids false negatives from retrieval failures---valid relationships are not missed due to search limitations
    \item Enables generation of cross-domain relationships that may not be be found in any single retrieved item of set of items.
    \item Leverages the LLM's ability to synthesize knowledge across its training corpus
    \item Query formulation becomes tractable: search for evidence of a \textit{specific} claim rather than open-ended exploration
\end{itemize}

\textbf{Limitations:}
\begin{itemize}[noitemsep]
    \item May generate more false positives (hallucinations) without retrieval grounding during generation
    \item Requires robust post-hoc validation to filter incorrect relationships
    \item Places greater burden on judge/validator components to distinguish valid from hallucinated edges
\end{itemize}

Our experimental design (RQ1a--RQ3) specifically evaluates whether post-hoc validation can adequately filter LLM-generated hallucinations, testing the viability of this generate-then-search paradigm for scientific knowledge synthesis.
Algorithmic details of the CLD generation pipeline (node generation + edge generation) are provided in Appendix~\ref{alg:cld_generation}, and the exact generator prompt used in the final experiments (Nitai\_C) is provided in Appendix~\ref{sec:generator_prompt_nitai_c}.

\subsubsection{Experimental Design Rationale}
\begin{itemize}[noitemsep]
    \item \textbf{GT Lit experiments:} CLD generation varies (seeds 10, 20, 30) $\rightarrow$ tests judge generalization across CLD instances
    \item \textbf{GT Synth experiments:} Corruption varies (seeds 1, 2, 3), base CLD fixed $\rightarrow$ isolates corruption detection ability
    \item \textbf{Seed separation:} Methodological independence between paradigms (10/20/30 vs 1/2/3)
\end{itemize}

\textbf{Confound Prevention:} The seed structure explicitly controls for potential confounds. In GT Synth experiments, fixing the base CLD while varying only the corruption seed ensures that performance differences reflect the judge's ability to detect different corruption patterns---not differences in underlying CLD structure. Any variation across runs is attributable solely to which edges were corrupted and how, eliminating CLD structure as a confounding variable. In GT Lit experiments, CLD structure variation is intentional: we deliberately test whether the judge generalizes across different valid CLD realizations rather than memorizing patterns from a single instance. The seed separation (10/20/30 for generation vs. 1/2/3 for corruption) maintains methodological independence, ensuring no overlap between the random states governing CLD creation and corruption processes.

\subsection{CLD Domains}
Three domain-specific Causal Loop Diagrams (CLDs) representing distinct scientific disciplines:
\begin{enumerate}[noitemsep]
    \item \textbf{Depressive Symptoms~\cite{uleman2024triangulation}:} Biopsychosocial model (14 variables, 34 edges) capturing feedback loops between cognitive, behavioral, and physiological factors in depressive states. Constructed via triangulation of group model building, literature review, and causal discovery.
    \item \textbf{Social Norms \& Obesity~\cite{crielaard2020socialnorms}:} Public health model (10 variables, 12 edges) representing interplay between social norms, body weight perception, and behavioral dynamics. Developed using system dynamics modeling with the HELIUS cohort.
    \item \textbf{Older Persons Emergency Department~\cite{smeekes2023emergency}:} Healthcare systems model (34 variables, 66 edges) of factors influencing older persons' ED utilization patterns. Constructed through group model building with interdisciplinary clinical experts.
\end{enumerate}
The exact ground-truth CLD datasets (including filenames and locations) are listed in Appendix~\ref{sec:data_availability} (Table~\ref{tab:gt_files}).

\textbf{Note on ``edges'' and validation edges used in evaluation.} Throughout Results, an \textbf{edge} is defined as an ordered (source, target) \textit{edge slot} with a relationship label in \{\texttt{POSITIVE}, \texttt{NEGATIVE}, \texttt{NONE}\}, i.e., the full directed pair set with \textit{Edges} $=|V|(|V|-1)$ represented by the \texttt{All Edges} table. The effective number of ground-truth validation edges used for scoring is the count of rows with \texttt{In Validation Graph = Yes} (so \textit{TP}+\textit{FN} equals the validation-edge count under this representation).
\textbf{Note on node generation vs.\ edge-only evaluation.} The system supports both node generation and edge generation (Appendix~\ref{alg:cld_generation}) and we evaluate node generation prompt robustness in Appendix~\ref{sec:ablation_node}; however, in the edge-level experiments (RQ1a/RQ1b/RQ2/RQ3) we \textbf{fix the node set to the validation CLD's ground-truth variables} and generate \textbf{edges only} to isolate edge discovery and downstream validation.

\textbf{Rationale:} Following system dynamics principles~\cite{sterman2002system}, variables acting on smaller temporal scales than the variable of interest can be averaged out, while variables on larger scales can be treated as constants. Similarly, spatial scale constrains whether causal relationships operate at the individual, community, or healthcare system level. The scope parameter further constrains the domain of variables the LLM should consider.

\subsection{CLD Selection Rationale}
Ground truth CLDs were selected from peer-reviewed publications with explicitly defined causal structures (named variables, directed edges, polarities). The three CLDs span distinct scientific domains---biopsychosocial health, public health behavior, and healthcare systems---reducing the risk of domain-specific overfitting. CLD sizes range from 12 to 66 edges (validation sets: Social Norms 12, Depressive 34, Older Persons ED 66), providing variation in system complexity.

\textbf{Limitation:} All three CLDs fall within the health domain, limiting generalizability to other fields (e.g., economics, ecology, engineering). Additionally, these CLDs represent expert-hypothesized relationships rather than empirically validated causal effects---a common limitation in complex systems where controlled experiments are infeasible~\cite{uleman2024triangulation,crielaard2020socialnorms,smeekes2023emergency}. Evaluation therefore measures reproduction of published expert models, which may or may not be causally correct.

\subsection{Edge Structure}
Each CLD edge contains: \textbf{source/target variables} (named entities with definitions), \textbf{relationship polarity} (\texttt{POSITIVE}/\texttt{NEGATIVE}/\texttt{NONE}), \textbf{causal motivation} (natural language mechanism explanation), and \textbf{scientific citations} (peer-reviewed references).

\subsection{Preliminaries}

This section documents design choices validated before the main experiments: generator model selection, temperature sensitivity, prompt selection, and random baseline methodology.

\subsubsection{Generator Model Selection}

Before running the main study, we performed a one-shot generator model comparison to select a single frontier LLM for all subsequent CLD generation experiments.

\textbf{Models compared.} We compared three generator models: GPT-4.1 (OpenAI), Sonar-Pro (Perplexity), and Claude Sonnet 4 (Anthropic).

\textbf{Dataset and setup.} For each of the three validation CLDs (Depressive, Social Norms, Emergency Dept), we generated a complete \texttt{All Edges} table using the same node set as the literature ground truth and the same generator prompt (Nitai\_C), with \texttt{temperature=0.7}. Corruption and judging were disabled (\texttt{corruption\_rate=0.0}, \texttt{judge\_edges=False}) so that models are compared purely on edge recovery against GT Lit.

\textbf{Metric computation.} For each model--CLD run, we compute confusion-matrix counts (TP/FP/FN) directly from the resulting \texttt{All Edges} sheet, then compute precision, recall, and F1:
\[
\text{Precision}=\frac{TP}{TP+FP},\quad
\text{Recall}=\frac{TP}{TP+FN},\quad
F1=\frac{2PR}{P+R}.
\]
We also compute an \textbf{aggregate micro-averaged} score by pooling TP/FP/FN across all three CLDs and recomputing precision/recall/F1 on the pooled counts (equivalent to micro-averaging over edges).

\textbf{Selection rule.} We select the generator with the highest aggregate (micro-averaged) F1, prioritizing balanced precision/recall. As a secondary constraint, we require token-level log probabilities (logprobs) for downstream UQ metrics extraction in RQ2; among the compared models, this is available for GPT-4.1.

\textbf{Reproduction.} The analysis is reproduced by \texttt{python final\_runs/generator\_model\_comparison\_analysis/analyze\_generator\_models.py}, which reads the per-model per-CLD result workbooks and computes the above metrics, and emits the thesis table \texttt{final\_runs/generator\_model\_comparison\_analysis/generator\_model\_comparison.tex}. The one-shot generation runs were produced using \texttt{final\_runs/generator\_model\_comparison\_analysis/run\_generator\_model\_comparison.py}.
Full configuration and script locations for this selection study are listed in Appendix~\ref{sec:generator_comparison} (Table~\ref{tab:generator_comparison_config}).

\subsubsection{Temperature Selection}

The generator temperature (T=0.7) was validated through a sensitivity analysis measuring how temperature affects the \textbf{generator's} ability to recover edges from literature-derived ground truth CLDs.

\textbf{Experimental Setup:}
\begin{itemize}[noitemsep]
    \item \textbf{CLDs:} All three validation CLDs: Social Norms (10 nodes, 12 edges), Depressive Symptoms (14 nodes, 34 edges), Older Persons Emergency Department (34 nodes, 66 edges)
    \item \textbf{Generator:} GPT-4.1 with Nitai\_C prompt (same as all other experiments)
    \item \textbf{Ground Truth:} Literature-derived CLDs (GT Lit)---published CLDs from peer-reviewed sources
    \item \textbf{Temperatures:} T$\in$\{0.0, 0.3, 0.5, 0.7, 1.0\} (5 levels spanning full range)
    \item \textbf{Runs:} 3 per temperature per CLD (seeds 10, 20, 30), totaling 45 generation experiments
    \item \textbf{Metric:} Edge F1 comparing generated edges against GT Lit (same metric as RQ1a GT Lit experiments)
\end{itemize}

\textbf{Statistical Analysis:} One-way ANOVA tested whether temperature significantly affects edge F1 performance. ANOVA assumptions (normality via Shapiro-Wilk, homogeneity via Levene's test) were verified. Effect size is reported as eta-squared ($\eta^2$), with interpretation following Cohen's guidelines: $<0.01$ negligible, 0.01--0.06 small, 0.06--0.14 medium, $\geq$0.14 large.

\textbf{Note on T=0.0:} While temperature=0.0 theoretically produces deterministic outputs, empirical testing showed variation across runs, confirming that OpenAI's API does not guarantee perfect reproducibility even at T=0.0~\cite{openai2024api}. This justifies including T=0.0 in the sensitivity analysis with multiple runs rather than a single run.

Results are presented in Table~\ref{tab:temperature_sensitivity} in the Results section.
The full experimental configuration and command entry point are documented in Appendix Table~\ref{tab:temp_sensitivity_config}.

\paragraph{Judge and Corrector Temperatures.}
For the evaluation and correction modules, temperature settings were selected based on their distinct functional roles, following established practices in the literature. The \textbf{Judge} (LLM-as-a-Judge) uses a low temperature (\texttt{T=0.0}--\texttt{0.4}) to maximize consistency and reproducibility of verdicts, minimizing stochastic variance in evaluation~\citep{liu2023gevalnlgevaluationusing, zheng2024judging}.

The \textbf{Corrector} uses a higher temperature (\texttt{T=0.7}) to facilitate exploration and diversity in generating refinements, preventing the model from collapsing into local minima where it cannot recover from an earlier error which next token generation is conditioned on, which can result from greedy decoding at \texttt{T=0.0}. This choice is supported by the Self-Refine framework which demonstrates the efficacy of iterative refinement with \texttt{T=0.7}~\citep{madaan2023selfrefineiterativerefinementselffeedback}.

The \textbf{Corruptor} also uses \texttt{T=0.7} with the same model as the generator (GPT-4.1) to create hallucinations that are stylistically indistinguishable from valid generations. LLMs exhibit self-preference bias~\citep{zheng2024judging}, favoring their own generation style. By matching the corruptor's model and temperature to the generator's, we minimize stylistic distributional shifts, ensuring that hallucinations must be detected based on \textit{content} rather than stylistic artifacts, thereby creating a more rigorous adversarial test.

\subsection{Generator Prompt Selection}

The generator prompts (Nitai\_C) used in all experiments were selected based on prior ablation studies:
The exact Nitai\_C generator prompt configuration used for node generation (\texttt{generateNodes}) and edge generation (\texttt{generateEdges}) is provided verbatim in Appendix~\ref{sec:generator_prompt_nitai_c} (Listing~\ref{lst:generator_nitai_c_yaml}).

\textbf{Edge Generation Ablation:} Nine prompt variants were evaluated across three CLDs, testing Chain-of-Thought (CoT), task decomposition, RAG/citation requirements, and relationship taxonomy complexity. The Nitai\_C variant (dual-level CoT with 6 relationship types) achieved the highest average F1 (0.460), outperforming baseline (0.371) by 24\%. Key findings: (1) CoT improved performance progressively (Nitai\_A$\rightarrow$B$\rightarrow$C), (2) mandatory citations reduced performance by 25\% (Nitai\_E vs. Nitai\_C), and (3) overly restrictive grounding caused complete failure (Cillian\_C: F1=0.00). See Appendix~\ref{sec:ablation_edge} for full results.

\textbf{Node Generation Ablation:} Seven prompt variants were evaluated in a 7$\times$3$\times$5 factorial design (105 runs total). ANOVA revealed no statistically significant differences between variants ($F=0.81$, $p=0.57$), with F1 scores ranging from 0.617 to 0.677. This suggests node generation is robust to prompt engineering choices, unlike edge generation. See Appendix~\ref{sec:ablation_node} for full results.

\subsubsection{Random Baseline Methodology}

To contextualize the LLM generator's performance, we establish a structural random baseline by computing expected edge F1 for Erd\H{o}s-R\'enyi random graphs G(n,m) matching each validation CLD's node and edge counts. This baseline represents the performance achievable by randomly selecting edges between the same nodes, without any causal reasoning.

\textbf{Random Baseline:} For each validation CLD, we generate 1000 random directed graphs with identical node sets and edge counts, computing edge precision, recall, and F1 against the ground truth. The 95\% CI is computed using the z-distribution (n=1000).

\textbf{LLM Generator:} Edge F1 is computed from 3 generation runs per CLD (seeds 10, 20, 30). Per-CLD 95\% CI uses the t-distribution (n=3).

Results are presented in Table~\ref{tab:random_baseline} and Figure~\ref{fig:random_baseline_final} in the Results section.
The baseline configuration and reproduction details are documented in Appendix~\ref{sec:random_baseline} (Table~\ref{tab:random_baseline_config}).

\subsection{RQ1: Judge Capability Verification (TruthfulQA)}
%==============================================================================

Before evaluating LLM-as-a-Judge on CLD-specific tasks, we first verify that the correctness-based judge shows baseline hallucination detection capability on TruthfulQA~\cite{lin2022truthfulqa}---a benchmark designed to test whether language models generate truthful answers. This sanity check helps ensure the evaluation pipeline behaves as expected before moving to the more domain-specific CLD setting; it does not, by itself, imply that any CLD-specific failures are purely domain-driven.
Exact execution commands, file locations, and the full configuration are provided in Appendix~\ref{sec:truthqa_verification} (Table~\ref{tab:truthqa_config}).

\subsection{Dataset}

\textbf{TruthfulQA:} A benchmark of 817 questions designed to elicit imitative falsehoods---answers that are false but would be produced by models trained on human text. Each question has both truthful and hallucinated answer variants.

\textbf{Sample Construction:} We construct a balanced dataset of 1,634 question-answer pairs:
\begin{itemize}[noitemsep]
    \item \textbf{Truthful answers (n=817):} Correct, factually accurate responses
    \item \textbf{Hallucinated answers (n=817):} Plausible but factually incorrect responses (imitative falsehoods)
\end{itemize}

\textbf{Task:} The judge must classify each answer as \texttt{CORRECT} (truthful) or \texttt{INCORRECT} (hallucinated) based solely on factual accuracy assessment.

\subsection{Performance Metrics}

Standard binary classification metrics with \texttt{Hallucinated} as the positive class:
\begin{itemize}[noitemsep]
    \item \textbf{Accuracy:} Overall correct classifications / total samples
    \item \textbf{Precision:} Of answers flagged as hallucinated, proportion that are actually hallucinated
    \item \textbf{Recall:} Of actual hallucinations, proportion correctly identified
    \item \textbf{F1 Score:} Harmonic mean of precision and recall
    \item \textbf{Specificity:} Of truthful answers, proportion correctly accepted
\end{itemize}

\subsection{Hypothesis}

If the correctness judge has genuine hallucination detection capability, we expect high performance on TruthfulQA (Accuracy $>$ 80\%, F1 $>$ 0.80). Strong TruthfulQA performance combined with weak CLD performance would indicate that CLD hallucinations are uniquely challenging---requiring domain expertise or citation verification that correctness judging alone cannot provide.

\subsection{RQ1a: LLM-as-a-Judge Hallucination Detection}
%==============================================================================

\subsubsection{Judge Definition}
\textbf{Input:} Variables, relationship type, causal narrative, prompt type

\textbf{Process:} LLM-as-a-judge~\cite{zheng2024llmasajudge} assesses edge against criteria (see Appendix~\ref{alg:judge_correctness} and~\ref{alg:judge_citation} for algorithmic details):
\begin{itemize}[noitemsep]
    \item \textbf{Type A (Correctness):} Verifies logical/scientific coherence of causal claim
    \item \textbf{Type B (Citation):} Verifies if Brave-fetched articles (up to 5) support causal narrative (see Appendix~\ref{alg:citation_fetcher} for citation fetching implementation details, including retries/timeouts and PDF fallback).
\end{itemize}

\textbf{Output Scores:}
\begin{itemize}[noitemsep]
    \item \textbf{Correctness:} 0=Incorrect, 0.5=Partially correct, 1=Correct
    \item \textbf{Citation:} 0=Not supported, 0.5=Partially supported, 1=Fully supported
\end{itemize}

\subsubsection{Prompt Variants}
\begin{enumerate}[noitemsep]
    \item \textbf{Baseline} (1500 max output tokens): Direct evaluation without scaffolding
    \item \textbf{Mechanistic} (1500 max output tokens): Structured multi-criteria evaluation using Bradford Hill-aligned framework~\cite{shimonovich2020bradford} (Plausibility, Temporality, Strength, Coherence)
    \item \textbf{Chain-of-Thought} (10000 max output tokens): Explicit step-by-step reasoning~\cite{kojima2022large} with systematic evaluation of causal logic
    \item \textbf{Mechanistic-Lit} (1500 max output tokens, citation judge only): Mechanistic prompt enhanced with explicit literature grounding requirements---evaluates whether causal mechanisms are documented in peer-reviewed sources
\end{enumerate}
Full prompt texts are provided verbatim in Appendix~\ref{sec:appendix_prompts} (correctness: Appendix~\ref{sec:correctness_prompts}; citation: Appendix~\ref{sec:citation_prompts}).

\textit{Note: Max output tokens (base: 1499/1500, mech: 255/1500, CoT: 1534/10000, mech-lit: 1487/1500) across variants (correctness, citation, corruption) no truncation detected. See Appendix~\ref{sec:token_verification} for per-variant breakdown.}

\subsubsection{Experimental Design}
\textbf{Sample:} 3 prompts $\times$ 3 CLDs $\times$ 3 runs = \textbf{27 runs} for correctness judging; 4 prompts $\times$ 3 CLDs $\times$ 3 runs = \textbf{36 runs} for citation judging (includes Mechanistic-Lit variant). See Table~\ref{tab:master} for complete configuration.

\subsubsection{Performance Metrics}
\begin{itemize}[noitemsep]
    \item \textbf{AUC-ROC:} Area under ROC curve (judge score vs. hallucination status)
    \item \textbf{Correlation ($r$):} Point-biserial correlation between judge score and hallucination label
    \item \textbf{Classification} (threshold: judge score $\leq 0.5$ = Hallucination): Precision, Recall, \textbf{F1} = $\frac{2 \cdot TP}{2 \cdot TP + FP + FN}$
\end{itemize}

\textbf{Baseline:} Random classification corresponds to AUC = 0.5 (diagonal on ROC curve). This represents the expected performance of a classifier that assigns labels uniformly at random, ignoring all input features. AUC = 0.5 means the classifier has no discriminative power---it cannot distinguish hallucinations from correct edges better than chance. Classifiers must exceed this threshold to demonstrate predictive value; AUC significantly above 0.5 indicates the model captures meaningful signal. We use this baseline throughout all ROC analyses.

Four distinct experiments are conducted, crossing two ground truth types with two judge types:

\paragraph{Human-LLM Agreement Validation.}
To validate that LLM citation judges produce reliable verdicts, we conducted human expert validation measuring inter-rater agreement between LLM judge outputs and a domain expert (Mick).

\subsubsection{Dataset}

\textbf{Sample:} 72 causal edges across 3 independent validation files, spanning 2 CLDs and 2 CLD-generating models:
\begin{enumerate}[noitemsep]
    \item \textbf{File 1 (MIck\_1):} 30 edges from Depressive symptoms CLD, generated by GPT-4.1
    \item \textbf{File 2 (Claude-4-sonnet):} 30 edges from Depressive symptoms CLD, generated by Claude 4 Sonnet
    \item \textbf{File 3 (result\_excel\_path):} 12 edges from Social norms CLD, generated by GPT-4.1
\end{enumerate}

\textbf{Human Validator:} Domain expert (Mick) provided categorical verdicts for each edge: Not supported (0), Partially supported (0.5), or Fully supported (1).

\textbf{LLM Judge:} Citation-based judge (GPT-4.1, temperature=0.0, baseline prompt) consistent with RQ1a experiments.

\subsubsection{Inter-Rater Reliability Metrics}

\begin{itemize}[noitemsep]
    \item \textbf{Cohen's $\kappa$:} Chance-corrected agreement measure; $\kappa = \frac{P_o - P_e}{1 - P_e}$ where $P_o$ = observed agreement, $P_e$ = expected agreement by chance
    \item \textbf{Agreement Rate:} Percentage of edges where LLM and human verdicts match exactly
    \item \textbf{Pearson $r$:} Correlation between LLM and human scores (0, 0.5, 1 scale)
\end{itemize}

\textbf{Interpretation (Landis \& Koch, 1977):} $\kappa < 0.20$ = slight; $0.21$--$0.40$ = fair; $0.41$--$0.60$ = moderate; $0.61$--$0.80$ = substantial; $> 0.80$ = almost perfect.

\subsubsection{Baseline Comparison}

To contextualize LLM-human agreement, we compare against human inter-rater reliability from prior GMB validation studies. A human-human baseline of $\kappa \approx 0.60$ (80\% agreement) on comparable expert validation tasks establishes the ceiling for automated judge performance.

\subsubsection{Hypothesis}

If citation-based LLM judges reliably assess evidence quality, we expect: (1) substantial agreement with human expert ($\kappa > 0.60$), (2) agreement comparable to or exceeding human inter-rater baseline, and (3) consistent performance across different CLDs and generators.

\paragraph{Physics CLD Validation.}
To verify that the judge can correctly identify valid causal relationships when they are unambiguous and well-supported, we constructed a "sanity check" dataset of four physics-based CLDs derived from fundamental laws:
\begin{enumerate}[noitemsep]
    \item \textbf{Thermostat Heating System:} Based on Newton's Law of Cooling (1701) and the First Law of Thermodynamics.
    \item \textbf{Predator-Prey Dynamics:} Based on the Lotka-Volterra equations (1925/1926).
    \item \textbf{RC Circuit:} Based on Ohm's Law (1827) and Kirchhoff's Laws (1845).
    \item \textbf{Water Tank:} Based on Pascal's Law (1663) and Torricelli's Law (1643).
\end{enumerate}
These CLDs contain 31 edges total across 26 variables. Compared to the complex biomedical domains, these relationships are typically specified as canonical laws/equations with well-defined variable meanings. The causal structures were extracted from standard physics textbooks and seminal papers (e.g., Newton, Lotka-Volterra). To reduce noise from low-quality or inconsistent narratives, we generated the edge rationales using Claude 4.5 Opus and checked them against the source texts. Using a high-capability model for motivation generation reduces the likelihood that downstream judge errors are driven primarily by poor input narratives. We evaluate them using both the Correctness Judge and the Citation Judge as a sanity-check setting under curated inputs.

\paragraph{Retrieval Success Analysis.}
To investigate whether low citation judge scores in complex domains are driven by retrieval failures (missing documents) or evidence characteristics (weak/hedged claims), we compare retrieval success rates across datasets with different citation sources:
\begin{enumerate}[noitemsep]
    \item \textbf{Expert-provided citations:} Physics CLDs (textbooks/papers) and Ulemans Alzheimer's CLD (150 edges with expert-curated references).
    \item \textbf{Automated web search:} The three main validation CLDs (Depressive, Social Norms, Emergency Dept) using the generate-then-search pipeline.
\end{enumerate}
For the Ulemans CLD, similar to the Physics CLDs, we generated the causal narratives (motivations) for each edge using Claude 4.5 Opus, grounded in the expert-provided relationships. We compute the retrieval success rate: the percentage of edges where the search system successfully fetches content from the target URL or query. Discrepancies between retrieval success and judge approval allow us to distinguish between infrastructure failures (cannot find paper) and validation failures (paper found but evidence weak).
The concrete definition of a “successful fetch” (content length/validity checks) and the full retry/backoff behavior are defined in Appendix~\ref{alg:citation_fetcher}.

\subsubsection{Uncertainty Quantification (UQ) Metrics}
\label{sec:uq_metrics_definition}
UQ metrics are computed solely from the generator LLM's internal signals during edge generation---they do not require external context (e.g., retrieved documents, knowledge bases) to evaluate. Concretely, they can be computed without retrieval or additional LLM calls at evaluation time. We capture four UQ metrics from generator logprobs and embeddings (see Appendix~\ref{alg:uq_metrics} for algorithmic details):

\begin{table}[H]
\centering
\footnotesize
\begin{tabular}{@{}lcc@{}}
\toprule
\textbf{Metric} & \textbf{Formula} & \textbf{Expected} \\
\midrule
Perplexity & $\displaystyle\exp\left(\frac{1}{n}\sum_{i=1}^{n} -\log P(x_i)\right)$ & $\uparrow \Rightarrow$ halluc \\[1.5ex]
Min Probability & $\displaystyle\min_i P(x_i)$ & $\downarrow \Rightarrow$ halluc \\[1.5ex]
Max Window Entropy & $\displaystyle\max_w \frac{1}{|w|} \sum_{t \in w} H_k(t)$ & $\uparrow \Rightarrow$ halluc \\[1.5ex]
Cosine Similarity & $\displaystyle\max_c \frac{\mathbf{e}_{narr} \cdot \mathbf{e}_c}{\|\mathbf{e}_{narr}\| \|\mathbf{e}_c\|}$ & $\downarrow \Rightarrow$ halluc \\
\bottomrule
\end{tabular}
\end{table}

Where: $P(x_i) = \exp(\text{logprob}_i)$, $H_k(t)$ = entropy over top-$k$ tokens, $\mathbf{e}$ = embeddings (mpnet, $d=768$)

\subsubsection{Implementation Choices}

\begin{table}[H]
\centering
\caption{UQ Metric Implementation Parameters and Rationale}
\label{tab:uq_params}
\footnotesize
\begin{tabularx}{\textwidth}{@{}l l l X@{}}
\toprule
\textbf{Parameter} & \textbf{Value} & \textbf{Source} & \textbf{Rationale} \\
\midrule
NLL cap & 20.0 (token), 10.0 (avg) & Design choice & Prevents single outlier tokens ($P < 2 \times 10^{-9}$) from dominating the average; average cap bounds perplexity to a finite maximum ($\leq e^{10} \approx 22{,}026$) to avoid extreme values \\

\bottomrule
\end{tabularx}
\end{table}

\textbf{Perplexity computation:} Two-stage capping improves robustness and avoids numerical instability: (1) individual token NLL values are capped at 20.0 before averaging ($\text{nll}_i = \min(-\log P(x_i), 20.0)$), preventing single outlier tokens ($P < 2 \times 10^{-9}$) from dominating; (2) the average NLL is capped at 10.0, bounding perplexity at $e^{10} \approx 22{,}026$ to prevent extreme values from overwhelming comparisons.

\textbf{Min Probability:} The minimum token probability across the entire generated sequence, representing the ``confidence floor''---the single least-confident token prediction. Low minimum probability indicates at least one token was generated with high uncertainty, which we treat as a candidate indicator of localized uncertainty. This metric is complementary to perplexity: while perplexity captures average uncertainty, min probability captures worst-case uncertainty.

\textbf{Max Window Entropy:} Two-step aggregation detects localized uncertainty spikes: (1) at each token position, compute entropy over top-$k=5$ alternatives returned by the API~\cite{openai2024api}: $H_k(t) = -\sum_{j=1}^{k} \tilde{p}_j \log \tilde{p}_j$ where $\tilde{p}_j = \text{softmax}(\text{logprob}_j)$; (2) apply a sliding window of size 5 to compute rolling averages via \texttt{np.convolve}, then return the maximum: $H_{\text{max-win}} = \max_i \frac{1}{w}\sum_{t=i}^{i+w-1} H_k(t)$. This identifies the highest-uncertainty region in the generated text.

\textbf{Cosine Similarity:} Embeddings are computed locally using \texttt{all-mpnet-base-v2}~\cite{reimers2019sentencebert} (768-dim, 384 token limit). Citation texts are chunked with adaptive window: chunk size $= \max(256, \min(4000, |\text{motiv.}|))$ characters, 20\% overlap, de-duplicated. This adaptive sizing ensures chunks remain within the model's 384-token context (motivations average 56 tokens, max 137; implied chunks 57--176 tokens). For each edge, $\text{sim} = \max_c \cos(\mathbf{e}_{\text{narr}}, \mathbf{e}_c)$ over all citation chunks. Available only for citation experiments.

\textbf{Model Selection:} We selected \texttt{all-mpnet-base-v2} based on benchmarking against Qwen3-Embedding-8B (Appendix~\ref{sec:embedding_benchmark}): 22$\times$ faster (3.0 vs.\ 67.3~ms/doc) with superior MTEB reranking performance (59.36 vs.\ 51.56)~\cite{muennighoff2023mteb}.

\subsubsection{Hallucination Definition}
$\text{Hallucination} = (\text{Classification} = \text{FP}) \lor (\text{Classification} = \text{FN})$ w.r.t. GT Lit

\subsubsection{Analysis Pipeline (6 Phases)}
\begin{enumerate}[noitemsep]
    \item \textbf{Phase 1-3:} Per-file analysis (N=63): AUC-ROC, Pearson $r$, t-test per UQ metric; aggregate meta-analysis
    \item \textbf{Phase 4 (RFE):} Recursive Feature Elimination~\cite{pedregosa2011sklearn} with 5-fold stratified CV on \textit{all} 16,507 pooled edges. Each classifier performs independent feature selection; best classifier (by CV AUC) determines features for Phase 5--6. Classifiers: LogReg, RF, GradBoost (Neural Network excluded---incompatible with RFE). \textit{Output:} Mean CV AUC across 5 folds per classifier; best classifier's selected features passed downstream.
    \item \textbf{Phase 5 (Ensemble):} Uses features from the best Phase 4 classifier (Random Forest selected all 4 UQ metrics) on 70/30 train-test split (stratified). Training set (70\%): 5-fold CV for model comparison. Test set (30\%): held-out final evaluation. Classifiers: all 4 (adds Neural Network). \textit{Output:} CV AUC (on training portion) + Test AUC (on held-out portion).
    \item \textbf{Phase 6 (Leave-One-CLD-Out):} Cross-domain generalization via leave-one-CLD-out CV. Train on 2 CLDs, test on held-out 3rd CLD; repeat for each of 3 CLDs. \textit{Output:} Mean AUC across 3 held-out CLD tests.
\end{enumerate}
The end-to-end classifier training/evaluation procedure is specified formally in Appendix~\ref{alg:classification}.

\subsubsection{Limitations}
UQ metrics not applicable for GT Synth (corruption post-generation, logprobs not captured). Cosine similarity only for Citation Judge (requires fetched embeddings).

\vspace{0.5em}

To test whether automated literature-based research can validate causal claims, we deploy a multi-agent Deep Research (DR) system that iteratively searches scientific literature for evidence supporting or refuting causal relationships. This section documents the system architecture and experimental design.
Exact execution commands and the full experimental configuration used in this study are provided in Appendix~\ref{sec:rq3_execution} (Table~\ref{tab:rq3_config}).

\subsubsection{Experimental Setup}

\textbf{Models:} The Deep Research system uses a two-tier model architecture:
\begin{itemize}[noitemsep]
    \item \textbf{Heavy model (GPT-5):} Used for complex reasoning tasks requiring high accuracy---hypothesis evaluation, article selection, causal evidence detection, judgment, and verdict synthesis. Temperature = 0.3.
    \item \textbf{Light model (GPT-5-mini):} Used for high-volume, lower-complexity tasks---iterative web search and evidence scoring. Temperature = 0.3.
\end{itemize}

\textbf{Framework:} PydanticAI~\cite{pydanticai2024} with typed agent definitions and structured JSON outputs via Pydantic models.

\textbf{Search API:} Brave Search API with academic domain filtering (23 trusted domains including PubMed, arXiv, Nature, NEJM, Cochrane Library).

\textbf{Parallelization:} Asynchronous execution via \texttt{asyncio.gather()} for parallel search threads and evidence scoring. Batch size = 5 edges processed concurrently.

\textbf{Run Date:} October 12--13, 2025.

\subsubsection{System Definition}
\label{sec:rq3_dr_system}

\textbf{Input:} Each CLD edge is converted to a causal claim in the format:
\begin{quote}
\texttt{"\{Source\} causes \{Target\}. \{Motivation\}"}
\end{quote}
where \textit{Source} and \textit{Target} are the variable names, and \textit{Motivation} is the natural language mechanism explanation from the CLD edge.

\textbf{Output:} For each edge, the system returns a structured verdict containing:
\begin{itemize}[noitemsep]
    \item \textbf{Verdict:} One of \texttt{supported}, \texttt{partially\_supported}, \texttt{unsupported}, or \texttt{inconclusive}
    \item \textbf{Confidence:} Self-assessed confidence score (1--10)
    \item \textbf{Direct Causal Evidence Found:} Boolean flag indicating whether direct (non-correlational) evidence was identified
    \item \textbf{Strongest Evidence:} URL, verbatim cited passage, and study type (e.g., RCT, meta-analysis) for the strongest causal evidence
    \item \textbf{Evidence URLs:} Complete list of supporting scientific sources
\end{itemize}

\subsubsection{Multi-Agent Architecture}

The system is implemented using the PydanticAI framework~\cite{pydanticai2024} with typed agent definitions and structured outputs. Seven specialized LLM agents are coordinated by a Python orchestrator class in a multi-iteration pipeline (see Appendix~\ref{alg:deep_research} for algorithmic details). The full multi-agent pipeline is documented in Table~\ref{tab:dr_agents} in Appendix~\ref{sec:dr_agents_appendix}.

\textbf{Model Selection:} GPT-5 (``heavy'' model) is used for complex reasoning tasks (hypothesis generation, judgment, causal detection, verdict synthesis), while GPT-5-mini (``light'' model) handles high-volume tasks (iterative search, evidence scoring) for cost efficiency.

\subsubsection{Pipeline Execution Flow}

The research process follows an 8-step pipeline with parallel execution where possible:

\begin{enumerate}[noitemsep]
    \item \textbf{Search Plan Generation:} The \texttt{hypothesis\_evaluator} generates 3--4 search queries based on the causal claim, plus the verbatim motivation as Query \#1 for direct matching.
    
    \item \textbf{Parallel Search Execution:} All queries execute in parallel via \texttt{asyncio.gather()}. Each query thread receives fresh conversation history to prevent token accumulation across threads. The \texttt{search\_agent} makes 4--6 iterative \texttt{web\_search} tool calls per query, with a hard limit of 5 searches per thread.
    
    \item \textbf{Evidence Scoring (Parallel):} All retrieved evidence is scored in parallel. Each source receives two scores:
    \begin{itemize}[noitemsep]
        \item \textit{Relevance} (1--10): How directly the evidence addresses the specific causal claim
        \item \textit{Quality} (1--10): Methodological rigor based on study design (RCTs $>$ cohort $>$ case-control $>$ cross-sectional)
    \end{itemize}
    
    \item \textbf{Smart Article Selection:} The \texttt{article\_selector} identifies 2--3 articles from snippets most likely to contain causal evidence based on causal language (``caused'', ``intervention'', ``RCT''), study design, and quality scores.
    
    \item \textbf{Full-Text Fetching:} Selected articles are fetched in full using BeautifulSoup HTML parsing (max 50K characters per article) to provide richer context for causal evidence detection.
    
    \item \textbf{Direct Causal Evidence Detection:} The \texttt{causal\_evidence\_detector} evaluates \textit{all} search results with strict criteria---only RCTs, experimental manipulations, natural experiments, and meta-analyses qualify as direct causal evidence. Correlational or observational studies are explicitly excluded.
    
    \item \textbf{Judgment:} The \texttt{judgment\_agent} assesses whether accumulated evidence supports the claim, providing confidence and optional claim modifications.
    
    \item \textbf{Final Verdict Synthesis:} The \texttt{verdict\_agent} integrates all evidence, scores, and judgments into a final verdict with key evidence summaries, limitations, and future research directions.
\end{enumerate}

\subsubsection{Search Infrastructure}

\textbf{Search Provider:} Brave Search API with academic domain filtering.

\textbf{Trusted Academic Domains (23):} Results from the following domains are prioritized: \texttt{pubmed.ncbi.nlm.nih.gov}, \texttt{arxiv.org}, \texttt{scholar.google.com}, \texttt{nature.com}, \texttt{science.org}, \texttt{cell.com}, \texttt{nejm.org}, \texttt{bmj.com}, \texttt{plos.org}, \texttt{frontiersin.org}, \texttt{springer.com}, \texttt{wiley.com}, \texttt{sciencedirect.com}, \texttt{tandfonline.com}, \texttt{sage.com}, \texttt{jstor.org}, \texttt{cochranelibrary.com}, \texttt{nih.gov}, \texttt{who.int}, \texttt{cdc.gov}, \texttt{academic.oup.com}, \texttt{cambridge.org}, \texttt{elsevier.com}.

\textbf{Query Enhancement:} All queries are automatically appended with ``scientific study research evidence'' to bias toward academic content.

\textbf{Retry Strategy:} 3 retries with exponential backoff for transient failures (status codes 429, 500, 502, 503, 504). Timeouts: 10s connect, 40s read.

\subsubsection{Early Stopping Criteria}

\subsubsection{Performance Metrics}

\textbf{Detection Rate:} The primary metric is the percentage of edges where \texttt{direct\_causal\_found = True}:
\[
\text{Detection Rate} = \frac{|\{e : \texttt{direct\_causal\_found}(e) = \texttt{True}\}|}{|E|} \times 100\%
\]
This measures the system's ability to find \textit{causal} (not just correlational) evidence in the scientific literature.

\textbf{TP-FP Discrimination Gap:}
\[
\Delta_{\text{TP-FP}} = \text{DetectionRate}_{\text{TP}} - \text{DetectionRate}_{\text{FP}}
\]
A positive gap indicates the system can distinguish expert-accepted edges from LLM hallucinations. We consider $\Delta > 20$ percentage points as meaningful discrimination.

\textbf{Confidence Scores:} Mean self-assessed confidence (1--10) by classification. Tests whether the system can reliably self-assess the validity of its findings.

\textbf{Hypothesis (H6):} If Deep Research can validate causal claims, we expect: (1) high detection rate for TP (expert-accepted edges should have literature support), (2) low detection rate for FP (hallucinations should lack support), and (3) significant TP-FP gap ($>$20 percentage points).

\subsubsection{Statistical Testing (Aggregate and Per-CLD)}

We test whether Deep Research discriminates between classes using pairwise two-sample proportion comparisons on the binary outcome \texttt{direct\_causal\_found}.

\textbf{Aggregate discrimination tests (pooled across CLDs).} We construct 2$\times$2 contingency tables of \textit{Found} vs.\ \textit{Not Found} for each pairwise comparison among TP, FP, and FN. For each pair, we report Fisher's exact test p-values and Cohen's $h$ effect sizes (with 95\% CI). We treat the three pairwise comparisons (TP--FP, TP--FN, FP--FN) as a single family and apply Bonferroni correction with $m=3$ ($\alpha_{\text{adj}}=0.05/3 \approx 0.017$), reporting both raw and adjusted p-values.

\textbf{Per-CLD discrimination tests.} To quantify domain dependence, we repeat the same three pairwise tests \textit{within each CLD} (Depressive, Social Norms, Older Persons). Within each CLD, we again apply Bonferroni correction over the three within-CLD pairwise tests ($m=3$) and report raw and adjusted p-values and Cohen's $h$.

\textbf{Implementation reference (reproducible).} Both the aggregate test table and the per-CLD pairwise table are generated by \texttt{python final\_runs/RQ3\_deep\_research/run\_rq3\_analysis.py}, which computes Fisher's exact tests, Cohen's $h$ (via the arcsine transform), and Bonferroni-adjusted p-values consistent with the Results tables (\texttt{rq3\_main\_table.tex} and \texttt{rq3\_per\_cld\_table.tex}).

\subsubsection{Exploratory Analysis: Ground Truth Enrichment}
\label{sec:gt_enrichment_method}

Beyond detection rate analysis, we explore whether Deep Research results could \textit{enrich} the expert-constructed ground truth. The hypothesis is that some FP edges (``hallucinations'') represent valid causal relationships that experts omitted due to time constraints, scope decisions, or disciplinary blind spots---not because they lack scientific support.

We evaluate two enrichment scenarios:

\textbf{Scenario 1: Enriched Ground Truth (FP Promotion)}
\begin{enumerate}[noitemsep]
    \item \textbf{Identify DR-validated FPs:} FP edges where \texttt{direct\_causal\_found = True}
    \item \textbf{Promote to TP:} Reclassify these edges as True Positives in an ``enriched ground truth''
    \item \textbf{Recompute metrics:} Calculate Precision, Recall, and F1 against the enriched GT
\end{enumerate}

\textit{Question:} ``What if experts missed valid literature-supported relationships?''

\textbf{Scenario 2: LLM+DR System (FP Promotion + FN Discovery)}
\begin{enumerate}[noitemsep]
    \item \textbf{Start with Scenario 1:} Enriched GT with promoted FPs
    \item \textbf{Identify DR-validated FNs:} FN edges where \texttt{direct\_causal\_found = True}
    \item \textbf{Add to system output:} In a complete LLM+DR pipeline, DR would search comprehensively and discover these literature-supported edges the LLM missed
    \item \textbf{Recompute metrics:} TP includes discovered FNs; FN decreases accordingly
\end{enumerate}

\textit{Question:} ``What could a complete LLM+DR system achieve if DR both validated LLM output AND discovered additional literature-supported edges?''

\textbf{Rationale:} Scenario 1 tests whether expert GT underestimates LLM quality. Scenario 2 tests the theoretical ceiling of an integrated LLM+DR pipeline where literature search augments generation.

\textbf{Critical Caveats (see Discussion for details):}
\begin{itemize}[noitemsep]
    \item \textbf{Domain variation:} FP promotion rates vary substantially across CLDs (28\% Depressive vs 76\% Older Persons), suggesting inconsistent enrichment
    \item \textbf{Evidence specificity/applicability:} DR may retrieve causal evidence that is only partially aligned to the exact edge claim (proxy variables, different operationalizations, or partial mechanisms); FP promotion should therefore be interpreted only after applicability thresholding and expert review
    \item \textbf{Circularity risk:} LLM-based DR validating LLM-generated edges could introduce systematic bias
    \item \textbf{No expert review:} Enrichment is automated; promoted edges require domain expert validation
    \item \textbf{Preliminary status:} Results are exploratory pending open-source dataset release for community validation
\end{itemize}

\textbf{Reproduction:} \texttt{python final\_runs/RQ3\_deep\_research/compute\_enriched\_gt\_metrics.py}

\subsubsection{Human Validation Sampling}
\label{sec:rq3_human_validation}

To validate the Deep Research verdicts, we performed stratified random sampling of edges for human review. From the 285 edges across all three CLDs, we first filtered to include only edges where direct causal evidence was identified (\texttt{direct\_causal\_found=True}), yielding 169 eligible edges. We then applied proportional stratified sampling across two dimensions: (1) CLD and (2) classification type (TP, FP, FN). Sample sizes for each stratum were calculated proportionally to their population size, with a minimum of one edge per stratum to ensure representation of all CLD-classification combinations. The target sample size was 50 edges (29.6\% of eligible edges). This resulted in 10 edges from the Depressive Symptoms CLD (29.4\%), 3 from Social Norms (27.3\%), and 37 from Older Persons (29.8\%), reflecting the underlying distribution. By classification, we sampled 9 TP edges (29.0\%), 32 FP edges (28.8\%), and 9 FN edges (33.3\%). Within each stratum, edges were selected using Python's \texttt{random.sample()} function with a fixed seed (42) for reproducibility. The final sample was then shuffled to randomize presentation order and prevent reviewer bias from sequential patterns.

\textbf{Reproduction:} \texttt{python final\_runs/RQ3\_deep\_research/scripts/sample\_edges\_for\_validation.py}

\vspace{0.25em}
\textbf{Human applicability rubric.} In addition to a categorical verdict (\texttt{causal}, \texttt{different\_vars, causal}, \texttt{invalid}), each sampled edge was assigned a continuous evidence applicability score \texttt{Fully applicable} \(\in[0,1]\), capturing how well the retrieved evidence matches the \textit{specific} (source, target, mechanism) claim rather than merely topical overlap. Scores were assigned using a coarse rubric: \(1.0=\) exact match; \(0.8\text{--}0.9=\) causal match but with different operationalizations/measures; \(\approx 0.7=\) partial claim match (e.g., evidence supports \(A\rightarrow B\) but the edge asserts \(A\rightarrow(B \wedge C)\)); \(\approx 0.6=\) analogous/proxy constructs; \(\le 0.5=\) weak/non-causal study design or otherwise insufficient evidence quality. This rubric is used in Results to choose an applicability threshold and to extrapolate from the validated sample to the full DR dataset.

\subsubsection{Threshold Selection and Sensitivity Analysis}
\label{sec:rq3_threshold_selection}

To determine an applicability threshold for filtering DR verdicts, we perform sensitivity analysis across threshold values $t \in \{0.5, 0.6, 0.7, 0.8, 0.9\}$.

\textbf{Sensitivity metrics.} For each threshold $t$, we compute on the validated sample:
\begin{itemize}[noitemsep]
    \item \textbf{Coverage (pass rate):} Fraction of edges with applicability $\geq t$
    \item \textbf{Correct-causal rate:} Fraction of passing edges labeled \texttt{causal} by human reviewer
    \item \textbf{95\% Wilson CI:} Confidence interval for the correct-causal rate
\end{itemize}

\textbf{Threshold selection rule (Elbow/Gradient).} We select the threshold using a gradient-based elbow rule on the coverage--correctness curve:
\begin{enumerate}[noitemsep]
    \item Construct the trade-off curve: $x(t) = \text{coverage}$, $y(t) = \text{correct-causal rate}$
    \item For each adjacent threshold pair moving from stricter to looser (e.g., $0.8 \rightarrow 0.7$), compute:
    \[
    \text{score} = \frac{\Delta \text{coverage}}{|\Delta \text{correctness}|}
    \]
    \item Select the threshold at the \textit{end} of the segment with maximum score (the ``elbow'' point where coverage gains diminish relative to correctness losses)
\end{enumerate}

This rule selects a threshold intended to balance including more edges (higher coverage) against maintaining evidence quality (higher correct-causal rate).

\subsubsection{Extrapolation from Validation Sample}
\label{sec:rq3_extrapolation}

To estimate enrichment potential for the full DR dataset from the 50-edge validated sample, we apply a two-stage extrapolation:

\textbf{Stage 1: Sample statistics.} From the validated sample at the selected threshold $t^*$:
\begin{itemize}[noitemsep]
    \item Compute the pass rate: fraction of validated edges with applicability $\geq t^*$
    \item Compute the correct-causal rate among passing edges (with Wilson 95\% CI)
\end{itemize}

\textbf{Stage 2: Full dataset projection.} For the full DR dataset ($n=285$ edges):
\begin{itemize}[noitemsep]
    \item Count edges where \texttt{direct\_causal\_found=True} per classification (FP, FN)
    \item Estimate edges above threshold: $\hat{n}_{\text{above}} = n_{\text{direct}} \times \text{pass\_rate}_{\text{sample}}$
    \item Estimate truly causal edges: $\hat{n}_{\text{causal}} = \hat{n}_{\text{above}} \times \text{causal\_rate}_{\text{sample}}$
    \item Conservative estimate uses the lower bound of the 95\% CI for causal rate
\end{itemize}

\textbf{Enrichment scenarios.} We compute projected F1 under two scenarios:
\begin{itemize}[noitemsep]
    \item \textbf{Scenario 1 (Enriched GT):} Promote estimated FP edges to TP in the ground truth
    \item \textbf{Scenario 2 (LLM+DR):} Additionally add estimated FN discoveries to system output
\end{itemize}

\textbf{Caveats:} Extrapolation assumes the validated sample is representative of the full dataset. The stratified sampling design ensures proportional representation, but small strata (e.g., Social Norms with $n=3$) have high sampling variance. Results are reported with point estimates and conservative (lower CI) bounds to reflect this uncertainty.

\textbf{Reproduction:} \texttt{python final\_runs/RQ3\_deep\_research/scripts/enrichment\_extrapolation.py}

This section consolidates the statistical framework used across all experiments, including power analysis, multiple comparison corrections, and sensitivity analysis methodology.

\subsection{Statistical Power}

Post-hoc power analysis assessed the probability of detecting observed effects at $\alpha = 0.05$ using achieved effect sizes (Cohen, 1988 conventions).

\subsubsection{RQ1a: Judge Prompt Sensitivity}
Friedman test with $k=3$ prompts (or $k=4$ for citation including Mechanistic-Lit), $n=9$ blocks (3 CLDs $\times$ 3 runs) per experiment type. Blocking on (CLD, run) pairs controls for instance-level variance while isolating the prompt effect. For correctness judges, observed effects were large (Kendall's $W = 0.48$--$0.70$), yielding achieved power $>0.99$. For citation judges, effects were small-to-medium (Kendall's $W \approx 0.29$--$0.30$). Effect sizes follow Kendall's W interpretation: $<0.1$ negligible, $0.1$--$0.3$ small, $0.3$--$0.5$ medium, $\geq 0.5$ large.

\subsubsection{RQ1b: Corrector Evaluation}
\textbf{Blocked (repeated-measures) design.} The corrector is evaluated over $n=9$ matched blocks per experiment, where each block corresponds to a unique (CLD, run) pair (3 CLDs $\times$ 3 runs). Within each block, we compare outcomes across corrector prompt variants, which controls for CLD-specific difficulty and run-to-run variation.

\textbf{Two distinct hypotheses.} We separate \textit{efficacy} from \textit{prompt effects}:
\begin{itemize}[noitemsep]
    \item \textbf{Efficacy (primary RQ1b question):} does the corrector improve performance relative to doing nothing? We test whether median $\Delta$F1 differs from 0 using a one-sample Wilcoxon signed-rank test on $\Delta$F1 (post-correction minus pre-correction) across the 9 blocks.
    \item \textbf{Prompt effect (secondary):} do prompt variants (Baseline, CoT, Mechanistic) differ \textit{under the same blocks}? We test this using a Friedman test with (CLD, run) as blocks and report Kendall's $W$ as effect size. When the omnibus Friedman test is significant, we run post-hoc paired Wilcoxon signed-rank tests between prompt pairs within the same blocks, with Bonferroni correction over the 3 pairs ($\alpha_{\text{adj}}=0.0167$).
\end{itemize}

\subsubsection{RQ2: Nested Data Structure}
Edge-level analyses ($n = 31{,}704$ edges) achieve power $\approx 1.0$ for any detectable correlation. However, edges are nested within CLDs ($n = 3$), creating a hierarchical structure. Cross-domain generalization claims are limited by the small number of independent clusters---empirically confirmed by leave-one-CLD-out validation showing substantial AUC degradation (RF: $0.987 \rightarrow 0.630$).

\subsubsection{RQ3: Deep Research}
Post-hoc power analysis assesses achieved power given the observed effect size and sample sizes. For the primary TP--FP discrimination test ($n_{\text{TP}}=44$, $n_{\text{FP}}=178$), we compute achieved power using a two-proportion z-test power formula. Additionally, we calculate the minimum detectable effect (Cohen's $h$) required to achieve 80\% power at $\alpha=0.05$, enabling assessment of whether the study was adequately powered to detect the observed effect. Power calculations are implemented using \texttt{statsmodels.stats.power}.

\subsection{Multiple Comparison Corrections}

Given the multiple statistical tests performed across research questions, we applied Bonferroni corrections to control family-wise error rate. Tests were grouped into families by research question, as each RQ addresses a distinct hypothesis:

\begin{itemize}[noitemsep]
    \item \textbf{RQ1a (Prompt Sensitivity):} For each of 4 experiments, Friedman omnibus test followed by pairwise Wilcoxon signed-rank post-hoc tests. With $k=3$ prompts, 3 pairwise comparisons per metric yield $\alpha_{\text{adj}} = 0.0167$; with $k=4$ prompts, 6 comparisons yield $\alpha_{\text{adj}} = 0.0083$.
    \item \textbf{RQ1b (Corrector prompt effect):} 2 omnibus Friedman prompt-effect tests (Synthetic and Ground Truth), Bonferroni correction across these two tests ($\alpha_{\text{adj}} = 0.025$). If omnibus tests are significant, we report post-hoc paired Wilcoxon prompt-pair comparisons within each experiment with Bonferroni correction over 3 pairs ($\alpha_{\text{adj}}=0.0167$). Efficacy vs.\ $\Delta$F1$=0$ is tested via one-sample Wilcoxon signed-rank tests on $\Delta$F1 (reported as supporting evidence for RQ1b).
    \item \textbf{RQ2 (UQ Metrics):} 4 single-metric tests, Bonferroni correction ($\alpha_{\text{adj}} = 0.0125$)
    \item \textbf{RQ3 (Deep Research):} 3 Fisher's exact tests, Bonferroni correction ($\alpha_{\text{adj}} = 0.017$)
\end{itemize}

All significant findings reported in the Results section survive correction: RQ1a prompt effects (Friedman $p < 0.05$, post-hoc $p < \alpha_{\text{adj}}$), RQ3 TP--FN and FP--FN discrimination ($p < \alpha_{\text{adj}}$). Non-significant findings (RQ1b, RQ3 TP--FP) remain unchanged. Both raw and Bonferroni-adjusted p-values are reported in result figures.

\subsection{Prompt Sensitivity Analysis (Sobol-Inspired; Blocked Design)}
\label{sec:sobol_sensitivity}

To quantify the impact of prompt engineering choices on system performance, we employ a variance-based sensitivity analysis framework \emph{inspired} by Sobol indices~\cite{sobol1993sensitivity}. For a \emph{single categorical} input, classical results connect variance decomposition in (functional) ANOVA to first-order Sobol sensitivity~\cite{saltelli2010variance}. However, our prompt experiments are not i.i.d.\ draws: performance is strongly confounded by CLD domain and run-level variation. We therefore use a \textbf{blocked (repeated-measures) design} with \textbf{CLD$\times$run as subjects} and \textbf{prompt as a within-subject factor}, reporting \textbf{partial $\eta^2$} as the proportion of \emph{within-subject} variance explained by prompt (see Appendix~\ref{app:sensitivity_analysis} for the full specification).

\subsubsection{Input Quantification}
We quantify the semantic difference between prompt variants by embedding each prompt using the MPNet sentence transformer~\cite{song2020mpnet} (768-dimensional) and computing pairwise cosine distances:
\begin{equation}
d(p_i, p_j) = 1 - \cos(\mathbf{e}_i, \mathbf{e}_j)
\end{equation}
where $\mathbf{e}_i$ is the embedding of prompt $p_i$. The variance of these pairwise distances, $\text{Var}(d)$, characterizes the semantic spread of the prompt set (e.g., small changes in wording vs. large structural changes).

\subsubsection{Output Variance Decomposition (Within-Subject)}
We quantify how much of the \emph{within-subject} variability in F1 scores (or other performance metrics) is explained by prompt choice. Using repeated-measures ANOVA, we report partial eta-squared ($\eta^2_p$):
\begin{equation}
\eta^2_p = \frac{SS_{\text{prompt}}}{SS_{\text{prompt}} + SS_{\text{error}}}
\end{equation}
For a single categorical factor under independent sampling, $\eta^2$ corresponds to the \textbf{first-order Sobol sensitivity index} ($S_1$)~\cite{saltelli2010variance}; we include the short derivation in Appendix~\ref{app:sobol_eta2_derivation}. In our blocked setting, $\eta^2_p$ plays the analogous role as a \emph{prompt sensitivity} measure after controlling for CLD$\times$run differences. We also report Cohen's $f$ for effect size interpretation.

\subsubsection{Normalized Sensitivity}
To relate input perturbation magnitude to output variance, we compute the normalized sensitivity:
\begin{equation}
S_{norm} = \frac{\eta^2_p}{\text{Var}(d)}
\end{equation}
Higher values indicate that small semantic changes in the prompt produce proportionally larger effects on output variance (high sensitivity), while low values indicate robustness.

\subsubsection{Scope}
\begin{itemize}[noitemsep]
    \item \textbf{Judge (RQ1a):} 4 experiments $\times$ 3--4 prompt variants (Baseline, CoT, Mechanistic, and Mechanistic-Lit for citation)
    \item \textbf{Corrector (RQ1b):} 2 experiments $\times$ 3 prompts (cumulative design)
\end{itemize}

\subsubsection{Theoretical Complexity}

\begin{itemize}[noitemsep]
    \item \textbf{Edge generation:} Parallel pairwise relationship discovery (\texttt{max\_workers=3--10})
    \item \textbf{Citation filling:} Parallel web search and document retrieval (\texttt{citation\_fill\_max\_workers=5})
    \item \textbf{Judging:} Parallel edge evaluation (\texttt{judge\_max\_workers=10})
\end{itemize}

\textbf{Theoretical speedup:} With $W$ workers and $E$ edges, wall-clock time scales as $O(E/W)$, providing up to $W\times$ speedup. In practice, speedup is limited by: (1) API rate limits (OpenAI: 10K RPM for GPT-4.1), (2) I/O overhead for web search, and (3) load balancing inefficiency for small $E$.

CV fold scores are not independent draws (folds share training data), so fold-based intervals should not be interpreted as strict confidence intervals regardless of $k$.

\subsection{Non-Parametric Testing Framework (RQ1a)}

For RQ1a prompt sensitivity analysis, we use non-parametric tests (Friedman + Wilcoxon) which do not require normality or homogeneity of variance assumptions. This choice is motivated by:
\begin{itemize}[noitemsep]
    \item \textbf{Small sample size:} With only $n=9$ blocks per experiment, parametric assumptions are difficult to verify reliably
    \item \textbf{Repeated-measures structure:} Blocking on (CLD, run) pairs creates a matched design naturally analyzed with Friedman
    \item \textbf{Robustness:} Non-parametric tests are robust to outliers and non-normal distributions
\end{itemize}

The Friedman test is the non-parametric equivalent of repeated-measures ANOVA, ranking observations within each block and testing whether rank sums differ across treatments. Post-hoc Wilcoxon signed-rank tests compare paired differences between specific prompts. Output figures include inline statistical annotations with Friedman p-values, Kendall's W effect sizes, and significant pairwise differences.

\subsection{RQ3 Analysis Methods (Deep Research Validation)}
\label{sec:rq3_analysis_methods}

RQ3 evaluates whether a Deep Research (DR) pipeline can discriminate between valid and hallucinated causal edges by finding \textit{direct causal evidence} in the literature. The RQ3 analysis is implemented in \texttt{final\_runs/RQ3\_deep\_research/} (see \texttt{rq3\_unified\_analysis.py} for the single-entry reproduction script).

\subsubsection{Primary Outcome: Detection Rate}
The primary outcome is the \textbf{detection rate}---the fraction of edges where the DR system reports \texttt{direct\_causal\_found=True}. Detection rates are computed overall and stratified by ground-truth class:
\[
\text{DetectionRate}_{c}=\frac{|\{e \in E_c : \texttt{direct\_causal\_found}(e)=\texttt{True}\}|}{|E_c|}\times 100\%,
\quad c\in\{\text{TP, FP, FN}\}.
\]
Counts and rates are computed from the DR output JSON files (see \texttt{rq3\_statistical\_test.py} and \texttt{rq3\_per\_cld\_detection\_rates.py}).

\subsubsection{TP--FP Discrimination Tests (Binary Proportions)}
To test whether DR discriminates between expert-accepted edges (TP) and hallucinated edges (FP), we construct a $2\times 2$ contingency table over \texttt{direct\_causal\_found} (found vs.\ not found) $\times$ (TP vs.\ FP) and report:
\begin{itemize}[noitemsep]
    \item \textbf{Primary test: Fisher's exact test} (always valid for $2\times 2$ tables; used as the preferred test in \texttt{rq3\_statistical\_test.py}).
    \item \textbf{Secondary test: Chi-square test} with explicit \textbf{assumption checks} using expected cell frequencies (Cochran's rule; see \texttt{check\_chi2\_assumptions} in \texttt{rq3\_statistical\_test.py}).
    \item \textbf{Gap reporting:} TP--FP gap in percentage points.
    \item \textbf{Effect size: Cohen's $h$} for proportion differences, \(h = 2\arcsin(\sqrt{p_1}) - 2\arcsin(\sqrt{p_2})\), with interpretation following Cohen (1988).
    \item \textbf{Cohen's $h$ CI:} 95\% confidence interval via a delta-method approximation (\(\mathrm{SE}(h)\approx\sqrt{1/n_1 + 1/n_2}\)).
    \item \textbf{Odds ratio:} with 95\% CI (Woolf method); a Haldane--Anscombe correction is applied if any cell is zero.
    \item \textbf{Post-hoc power analysis:} achieved power for the observed effect size and the minimum detectable effect at 80\% power (implemented in \texttt{rq3\_statistical\_test.py}).
\end{itemize}

\subsubsection{Multiple Comparisons Within RQ3}
RQ3 performs three pairwise class comparisons (TP vs.\ FP, TP vs.\ FN, FP vs.\ FN) using Fisher's exact tests; p-values are Bonferroni-adjusted within this family (\(m=3\), \(\alpha_{\text{adj}}=\alpha/m\)). This is implemented in \texttt{bonferroni\_correction} in \texttt{rq3\_statistical\_test.py}.

\subsubsection{Per-CLD Breakdown}
Detection rates are also computed per CLD and per class (TP/FP/FN) to characterize domain variation (see \texttt{rq3\_per\_cld\_detection\_rates.py}).

\subsubsection{Human Validation: Stratified Sampling}
To validate DR outputs, we perform stratified random sampling of edges for human review using \texttt{scripts/sample\_edges\_for\_validation.py}. Sampling is stratified by (1) CLD and (2) class (TP/FP/FN), uses proportional allocation with a minimum of one edge per stratum when non-empty, and fixes the random seed (42) for reproducibility. Consistent with the study design, sampling is performed on the subset of edges with \texttt{direct\_causal\_found=True} (i.e., edges where DR claims direct causal evidence).

\subsubsection{Threshold Sensitivity, Selection, and Extrapolated Enrichment}
Human validation includes a continuous \textbf{applicability} score (\texttt{Fully applicable} \(\in[0,1]\)) and categorical labels (\texttt{causal}, \texttt{different vars, causal}, \texttt{invalid}). Using the validated sample, we:
\begin{itemize}[noitemsep]
    \item \textbf{Compute Wilson 95\% CIs} for correct-causal rates at each threshold (\texttt{wilson\_ci} in \texttt{scripts/enrichment\_extrapolation.py}).
    \item \textbf{Run sensitivity analysis} over thresholds \(t\in\{0.5,0.6,0.7,0.8,0.9\}\), reporting coverage (pass rate) and correct-causal rate among passing edges.
    \item \textbf{Select a threshold} using an \textbf{elbow/gradient decision rule} (Option B): for adjacent thresholds (stricter\(\rightarrow\)looser), compute \(\Delta\)coverage$/|\Delta|$correctness and choose the threshold at the end of the best segment (implemented in \texttt{select\_threshold\_by\_gradient}).
    \item \textbf{Extrapolate enrichment} to the full dataset by applying the validated pass rate and correct-causal rate to the population of eligible edges (those with \texttt{direct\_causal\_found=True}) to estimate FP promotions (Scenario 1) and FN discoveries (Scenario 2).
\end{itemize}
This pipeline is implemented in \texttt{scripts/enrichment\_extrapolation.py} and \texttt{scripts/compute\_enriched\_f1\_from\_validation.py}, which also generate reproducible LaTeX artifacts in \texttt{thesis/final\_thesis/generated/}.

\subsection{RQ2 Block-Level Statistical Framework}
\label{sec:rq2_stats}

RQ2 investigates the discriminative power of uncertainty quantification (UQ) metrics. To account for the hierarchical structure of the data---where multiple files (prompts, experiment types) share the same underlying CLD generation run---we adopt a \textbf{block-level aggregation} strategy for statistical inference, treating the generation run block (CLD $\times$ Run, $N=9$) as the independent unit of analysis.

\begin{itemize}[noitemsep]
    \item \textbf{Unit of Analysis:} Inference is performed on $N=9$ independent blocks (3 CLDs $\times$ 3 runs). Within each block, metric performance (AUC, correlation) is averaged across prompts to marginalize over prompt-specific variation.
    \item \textbf{Hypothesis Testing:} We test whether the mean block-level AUC exceeds chance (0.5) using a \textbf{one-sample Wilcoxon signed-rank test} on the 9 block means. This non-parametric test is robust to non-normality and outliers in the small-sample setting.
    \item \textbf{Uncertainty Quantification:} 95\% confidence intervals for the mean AUC are computed via \textbf{bootstrap resampling over blocks} (10,000 resamples). This preserves the dependence structure within blocks while quantifying sampling variability across generation runs.
    \item \textbf{Correlation Aggregation:} Pearson correlations ($r$) are aggregated across blocks using the \textbf{Fisher z-transformation} to stabilize variance and avoid bias, then transformed back to the correlation scale for reporting.
    \item \textbf{Distributional Comparisons:} For visualizing separation between hallucinated and correct edges (e.g., Figure~\ref{fig:rq2_distributions_by_cld}), we employ the Mann-Whitney U test on pooled edge distributions per CLD, acknowledging that this treats edges as the unit of description rather than inference.
\end{itemize}

\subsection{Effect Size Reporting}

All significant findings include standardized effect sizes with interpretation following Cohen (1988):
\begin{itemize}[noitemsep]
    \item \textbf{Cohen's $f$ (ANOVA):} $<$0.10 negligible, 0.10--0.25 small, 0.25--0.40 medium, $\geq$0.40 large
    \item \textbf{Cohen's $d$ (paired differences):} $<$0.20 negligible, 0.20--0.50 small, 0.50--0.80 medium, $\geq$0.80 large
    \item \textbf{Cohen's $h$ (proportions):} Same thresholds as $d$
    \item \textbf{Pearson $r$ (correlation):} $<$0.10 negligible, 0.10--0.30 small, 0.30--0.50 medium, $\geq$0.50 large
\end{itemize}
